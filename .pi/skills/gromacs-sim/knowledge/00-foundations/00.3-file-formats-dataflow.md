# 00.3 — File Formats & Data Flow

## The pipeline at a glance

```
 .pdb (experimental)
   │  pdb2gmx  (force field → topology + gro)
   ▼
 .gro + .top ( + ligand .itp )
   │  solvate → .gro (solvated)
   │  genion  → .gro (ions) + updated .top
   │  grompp  (.top + .mdp + .gro → .tpr)
   ▼
 .tpr  (run input: topology + params + coords + velocities, binary, portable)
   │  mdrun
   ▼
 .xtc/.trr/.tng (trajectory)  +  .edr (energy)  +  .log  +  .cpt (checkpoint)
   │  trjconv / trjcat (PBC fix, fit, convert)
   ▼
 analysis inputs (cleaned .xtc/.gro + .ndx index)
```

## Structure files

| Ext | Content | Notes |
|-----|---------|-------|
| `.pdb` | Coordinates (Å), standard | Experimental input; alt-locs, missing atoms common. |
| `.gro` | Coordinates (nm, 3 dp), box vectors, NATOMS | GROMACS native; fixed-width; **low precision** (3 decimals) — fine for input, not for exact restart. |

## Topology files

| Ext | Content | Notes |
|-----|---------|-------|
| `.top` | Main topology: `[defaults]`, `[moleculetype]` blocks, `[system]`, `[molecules]` | Order of `[molecules]` must match coordinate-file order. |
| `.itp` | Included topology (usually one molecule/ligand) | `#include "ligand.itp"`; directives have strict ordering. |

See `00.4` for full anatomy.

## Parameter file

| Ext | Content | Notes |
|-----|---------|-------|
| `.mdp` | Run parameters (integrator, dt, coupling, cutoffs, output) | One per phase (em.mdp, nvt.mdp, npt.mdp, md.mdp). See `00.5`. |

## Run input

| Ext | Content | Notes |
|-----|---------|-------|
| `.tpr` | **Self-contained**: topology + MDP params + coords + velocities | Binary, portable, **version-specific**. The only input `mdrun` needs. Regenerate with `grompp` when MDP/topology changes. |

## Trajectory files

| Ext | Content | Precision / size | Notes |
|-----|---------|------------------|-------|
| `.xtc` | Positions | Compressed (~4 B/atom/frame), lossy | Still the **default** compressed output of `mdrun -x` (default filename `traj_comp.xtc`); small, fast. |
| `.trr` | Positions + velocities + forces | Full precision, large | When you need forces/velocities every frame. |
| `.tng` | Coordinates, velocities, forces, and/or energies (any combination) | Compressed, portable, any precision | **First-class trajectory format in 2026.3** — `mdrun -x` accepts `.tng` ("tng format or portable xdr format"); MDP output options (`nstxout`, `nstvout`, `nstfout`, `nstenergy`) control which data go in and how lossy the compression is. Full-precision alternative to `.trr`. Read with `gmx dump -f traj.tng` / `gmx check -f traj.tng`. |
| `.h5md` | Positions (+vel) | HDF5-based | **Experimental** (2026), opt-in. |

## Energy / log / checkpoint

| Ext | Content | Notes |
|-----|---------|-------|
| `.edr` | Energy terms, pressure tensor, box, COM velocity, (λ derivatives, AWH data) | Read with `gmx energy`. |
| `.log` | Human-readable run log, warnings, performance | **Always read** after a run; first place to look for problems. |
| `.xvg` | Plot data (e.g. `dhdl.xvg` for free energy) | Plot directly. |
| `.cpt` | **Full-precision** positions + velocities + algorithm state (thermo/barostat, λ) | `state.cpt` / `state_prev.cpt`. Enables **exact** restart. |
| `.xpm` | Image (density, order) | Render with `xpm2ps`. |

## Index file

| Ext | Content | Notes |
|-----|---------|-------|
| `.ndx` | Named groups of atom (or molecule/angle/dihedral) numbers | Used by nearly every analysis tool. Build with `make_ndx`/`select`/`mk_angndx`. |

## Other

| Ext | Content |
|-----|---------|
| `.dat` | Generic data (e.g. PLUMED output, AWH) |
| `.tex`/`.eps` | Plots |
| `.rtp`/`.hdb`/`.ff` | Force-field residue database (read-only, from the FF) |
| `.g96` | Gromos 96 structure (legacy) |

## Practical rules

1. **`.tpr` is the contract.** If anything (topology, MDP, coords) changes,
   re-run `grompp`. `mdrun` only ever reads a `.tpr` (plus `-cpi` for restart).
2. **Restart precision**: `.cpt` restart is exact; restarting from `.gro` loses
   precision and all coupling-algorithm state → not a true continuation.
3. **Trajectory choice**: `.xtc` (small) for most analysis; `.tng` (compact,
   can carry x/v/f/energies) or `.trr` when velocities/forces matter; never
   write full-precision every frame in production (I/O bound). To get `.tng`
   output, name the `-x` file with a `.tng` extension (the default remains
   `.xtc`).
4. **`.gro` is 3-decimal nm** — do not use it as the source of truth for
   coordinates after a run; use the trajectory or `.cpt`.
5. **`#name.N#` auto-backups**: any tool re-writing an existing output
   renames the old one to `#name.1#`, `#name.2#`, … — re-running a tool (e.g.
   the analysis suite) leaves full stale copies behind. They are transient;
   disposal policy is KB 01.10.
