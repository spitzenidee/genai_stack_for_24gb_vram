# 00.4 — Topology Anatomy (`.top` / `.itp`)

## Directive ordering (strict)

A topology file is a sequence of **directives** (sections) and **preprocessor**
lines. Order matters; violating it yields `Invalid order for directive`.

1. `#include "..."` / `#define` / `#ifdef` — preprocessor (anywhere a directive
   is allowed, but `#include` of a file containing directives must land in a
   valid position).
2. `[ defaults ]` — **exactly once, and first** among topology directives. In
   practice it comes from the force field: the main `.top` **must start with**
   `#include "<ff>.ff/forcefield.itp"` (that include provides the single
   allowed `[ defaults ]`). Without it, `grompp` rejects the first
   `[ moleculetype ]` with the misleading `Invalid order for directive
   moleculetype`.
3. One or more `[ moleculetype ]` blocks.
4. `[ system ]` — system name (single line). **Required in 2026.3**: omitting
   it (or putting `[ molecules ]` without a preceding `[ system ]`) is a
   fatal `grompp` error.
5. `[ molecules ]` — name + count, **one per line, order must match the
   coordinate file**.

## `[ defaults ]`

```
; fcn  a     b     c            d            r   n
  1   1.0     1.0   0.0          0.0          1.0 1
```
Sets the 1-4 scaling factors (`factor_vdw`, `factor_coulomb`) and exclusions
used across the file. Must match the force-field convention.

## `[ moleculetype ]` block

```
[ moleculetype ]
; name  nrexcl
Protein  3
```
- `nrexcl`: exclude interactions up to N bonds apart (typically **3** or **5**;
  must match the FF). 1-4 pairs (when `nrexcl=3`) are handled via `[ pairs ]`.

Sub-sections **inside** a moleculetype (order within the block is fixed):

| Section | Content |
|---------|---------|
| `[ atoms ]` | `#  type  res# resname  atom  cgn  charge  mass` — **atom names must exactly match the coordinate file** |
| `[ settles ]` | SPC/EW water triads (3 atoms, no bonds needed) |
| `[ bonds ]` | `i  j  func  length  k` |
| `[ angles ]` | `i  j  k  func  angle  k` |
| `[ dihedrals ]` | `i  j  k  l  func  angle  k  multiplicity` (proper + improper types) |
| `[ pairs ]` | 1-4 interactions: `i  j  func  r  epsilon  sigma` |
| `[ virtual_sites2/3/N ]` | Virtual interaction sites (dipoles, etc.) |
| `[ constraints ]` | `i  j  func  length  k` (optional explicit constraints) |
| `[ position_restraints ]` | `atom  type  fcx  fcy  fcz` — must live in the moleculetype it belongs to |
| (none) | Nonbonded parameters come from `[ atomtypes ]` (per atom type); 1-4 interactions from `[ pairs ]` / top-level `[ pairtypes ]` — there is no `[ nonbonded ]` or `[ cgenff_nons ]` section |

## Charge groups

- A **charge group** is a set of atoms that moves as a unit for PME and
  domain-decomposition. New charge groups start at atoms marked with a new
  `cgn` (charge-group number) in `[ atoms ]`, or at molecule boundaries.
- **Large charge groups** (e.g. a big ion or a fully charged ligand kept as one
  group) increase the **minimum DD cell size** → can break parallel runs
  (`no domain decomposition for n ranks ...`). Splitting charged molecules into
  smaller charge groups can help scaling.

## Exclusions & 1-4

- Atoms within `nrexcl` bonds are **excluded** from nonbonded lists.
- 1-4 pairs (3 bonds apart) get special scaling from `[ defaults ]`
  (`factor_vdw`, `factor_coulomb`) and are listed in `[ pairs ]` when
  `nrexcl=3`.
- **Do not** hand-edit exclusions to "fix" a cutoff error — that breaks the
  minimum-image convention (see `01.9`).

## Position restraints

- `[ position_restraints ]` with force constants (kJ/mol/nm²) per atom.
- Generate with `gmx genrestr -fc 1000` (default). Staged relaxation uses lower
  constants (see `02.02`).
- A posre `.itp` **belongs to exactly one moleculetype** — including it in the
  wrong place causes `Atom index (n) in position_restraints out of bounds (1-N)`.

## `[ system ]` and `[ molecules ]`

```
[ system ]
Protein in water

[ molecules ]
Protein  1
SOL     45210
NA        12
CL        12
```
- **`[ system ]` is required** (before `[ molecules ]`) — a topology without
  it fails `grompp` with a fatal error in 2026.3.
- Every name here must have a matching `[ moleculetype ]` defined earlier
  (else `Fatal error: No such moleculetype XXX`).
- **Order must match the `.gro`/`.pdb`** atom order (else `XXX non-matching
  atom names`).

## Ligand / custom molecule

1. Parameterize (see `00.6`) → `ligand.itp` (a full moleculetype) + `ligand.gro`.
2. `#include "ligand.itp"` in the main `.top` (before `[ system ]`).
3. Add `LIG 1` to `[ molecules ]` and the ligand atoms to the coordinate file
   (order consistent).
4. Regenerate `.tpr`.

## Common topology mistakes (→ `01.9`)

- `[defaults]` not first / duplicated.
- Main `.top` missing `#include "<ff>.ff/forcefield.itp"` → `Invalid order for
  directive moleculetype` (the include provides the required `[ defaults ]`).
- Atom-name mismatch between `.top` and `.gro`.
- `[molecules]` order ≠ coordinate order.
- Missing `[moleculetype]` for a name in `[molecules]`.
- Posre file in the wrong moleculetype.
- Non-integer cumulative charge (topology bug) → `System has non-zero total
  charge`.
