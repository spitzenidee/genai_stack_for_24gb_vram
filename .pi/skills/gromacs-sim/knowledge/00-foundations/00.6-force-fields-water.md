# 00.6 — Force Fields, Water Models, Ligand Parameterization

## All-atom protein force fields

| FF | `pdb2gmx -ff` | Notes |
|----|---------------|-------|
| **AMBER** | `amber99sb-ildn`, `amber14sb` (2026), `amber19sb` (2026) | Popular for proteins; 14SB/19SB are the newer refinements. Pair with OPC/OPC3 water (2026) or SPC/E. |
| **OPLS** | `oplsaa` | Common; pair with SPC/E. |
| **CHARMM** | `charmm27` | Pair with TIP3P. **CHARMM36 is not shipped** in this build (only `charmm27.ff`). |
| **GROMOS** | `gromos54a7` | Pair with OPC/SPC/E per FF docs. (No `gromos56a7` in this build.) |

**Rule**: the force field, water model, and ion parameters must be a
**matched set** (each FF validates specific water/ion types). Mixing an AMBER
protein with TIP3P "because it's convenient" is a methodology error.

## Water models

| Model | `pdb2gmx -water` / `solvate` | Typical partner |
|-------|------------------------------|-----------------|
| **SPC/E** | `spce` | AMBER, OPLS (classic default) |
| **TIP3P** | `tip3p` | CHARMM |
| **TIP4P/2005** | `tip4p` | AMBER/OPLS (better density/diffusion) |
| **TIP4P-Ew** | `tip4pew` | AMBER/OPLS (TIP4P with Ewald summation) |
| **TIP5P** | `tip5p` | High accuracy, expensive |
| **OPC** | `opc` (2026) | AMBER14SB/19SB |
| **OPC3** | `opc3` (2026) | AMBER14SB/19SB |

- Water is added by `gmx solvate -cp solute.gro -cs <waterbox.gro> -p topol.top`.
  The **water model is set by the topology** (the `#include "<ff>/<model>.itp"`
  from `pdb2gmx -water`), not by `solvate`. `solvate` only supplies coordinates:
  the default `-cs` box is `$GMXLIB/spc216.gro` (SPC), and **these coordinates
  also work for any other 3-site model** (SPC/E, TIP3P, OPC, OPC3) since a
  short equilibration removes the small differences. For 4-site models use a
  4-site box (e.g. `$GMXLIB/tip4p.gro` for TIP4P/2005).
- **CHARMM + SPC nuance**: TIP3P is the canonical CHARMM water model (the FF is
  parameterized against it), so **default to `tip3p`**. The matched-set rule is
  about the water **model** (the `.itp` parameters in the topology), not the
  coordinate box (SPC coords are fine with any 3-site model, above). **SPC +
  CHARMM36 is an acceptable, literature-attested choice** (both are 3-site rigid
  models) — do not reject it if a user requests it or is reproducing a study that
  used SPC, but record the deviation from the canonical TIP3P partner in the
  RUNLOG. (This acceptance was informed by Pymacs, which runs
  `-water spc -ff charmm36`.)
- **Water `.itp` include paths changed in 2026.3**: top-level `spc.itp`,
  `spce.itp`, `tip3p.itp`, `tip4p.itp`, etc. are now **`#error` stubs**
  ("This top-level .itp file has been removed. Edit your topology to include it
  from your force field directory instead"). Include from the FF directory:
  `#include "oplsaa.ff/spce.itp"`, `#include "amber14sb.ff/opc.itp"`, etc.
  (`amber14sb.ff`/`amber19sb.ff` ship `opc.itp`, `opc3.itp`, `spc.itp`,
  `spce.itp`, `ions_opc.itp`, `ions_opc3.itp`.)
- **SETTLE** constraint (`constraints = h-bonds` applies SETTLE to water) is
  required for the standard 2 fs timestep with 3-site waters.

## Ion parameters

- `gmx genion` reads ion types from the **topology** (via `-s topol.tpr` or
  `-p topol.top`, which must `#include` the FF's `ions.itp`). Names are
  FF-specific (`NA` vs `Na+` etc.) — use the names present in your FF's ion
  set.
- Key flags (2026.3): `-np`/`-pname`/`-pq` (number/name/charge of positive
  ions), `-nn`/`-nname`/`-nq` (negative), `-conc` M (overrides `-np`/`-nn`),
  `-[no]neutral` (default no — with `-conc` you must neutralize yourself or
  pass `-neutral`), `-rmin` (0.6 nm), `-seed`. **No `-select`/`-pdb` flags.**
- Physiological salt ≈ **0.15 M** (`genion -conc 0.15 -neutral`) after
  neutralization.

## Ligand / small-molecule parameterization

Ligands are **not** in the standard residue DB — parameterize first:

| Target FF | Typical route |
|-----------|---------------|
| AMBER | `antechamber` (sqm/AM1-BCC charges) + `tleap`, or **ACPYPE** |
| CHARMM | **CGenFF** (web) → GROMACS-format `.itp`/`.prm` (full workflow below) |
| OPLS | **ACPYPE** or manual OPLS assignment |
| GROMOS | Manual / `gromos` ligand tools |

General workflow (any route):
1. 3D structure + protonation state (pH) → `.mol2`/`.pdb`.
2. Generate charges + FF types → `ligand.itp` + `ligand.gro` (+ `ligand.mol2`).
3. `#include "ligand.itp"` in `.top`; add to `[ molecules ]`.
4. **Validate**: check the ligand's charge, atom names, and that a short
   vacuo/EM test is stable before solvating.

### CGenFF (CHARMM) workflow — worked example (2-propylphenol, `JZ4`)

The most mature CHARMM route is the **CGenFF** web server
(<https://cgenff.com>, free for academic use, registration required). CGenFF is
both a parameter set (CHARMM-compatible) and a program that assigns
small-molecule topologies by analogy. This is the full, validated workflow
(Lemkul Tutorial 3, `JZ4` ligand).

**1. Input preparation (`.mol2`)**
- Start from 3D coordinates (crystal ligand, e.g. `jz4.pdb`) at the target-pH
  protonation state.
- Open in **Avogadro** (<https://avogadro.cc>), *Build → Add Hydrogens*, save as
  `jz4.mol2`. The mol2 carries atom names, coordinates, **TRIPOS atom types**,
  charges, and bonded connectivity.
- Fix the residue name: the line under `@<TRIPOS>MOLECULE` may read `*****` —
  replace with the 3-letter resname (e.g. `JZ4`).
- Fix residue name/number of the added hydrogens: **every** atom must share the
  same resname and residue number `1` (Avogadro may tag added H's with a
  different resname such as `JZ167`/`UNL1`).
- **Sort the bonds**: the `@<TRIPOS>BOND` section must be in **ascending atom
  number** order (atoms on each line ascending; bonds ordered by first atom,
  then second). CGenFF requires this. Use the tutorial's `sort_mol2_bonds.pl`:
  `perl sort_mol2_bonds.pl jz4.mol2 jz4_fix.mol2`
  (the tutorial text has a typo `jz4.mo2`; the correct input is `jz4.mol2`).

**2. Server**
- Upload `jz4_fix.mol2` to <https://cgenff.com>.
- The server returns a CHARMM stream file (`jz4.str`) and a GROMACS-format
  download (*Convert to GROMACS → Download GROMACS format* → ZIP with
  coordinates + topology).

**3. Penalty score (quality gate)**
Inspect the penalty scores in `jz4.str` — CGenFF assigns parameters by analogy
and the penalty measures the analogy quality:

| Penalty | Meaning | Action |
|---------|---------|--------|
| < 10 | reliable | use as-is |
| 10–50 | some refinement may be needed | at minimum basic validation: QM potential-energy scans (bonded terms), QM water interactions (charges) |
| > 50 | poor analogy | significant manual refinement / reparametrization required |

(JZ4 2-propylphenol: charge and new-dihedral penalties are both < 1 → usable
directly.)

**4. GROMACS integration (server output needs surgery)**
The server's `jz4_fix_gmx.top` is a *standalone system topology*. Adapt it into
a reusable ligand `.itp`:
1. `cp jz4_fix_gmx.top jz4_gmx.itp`
2. Remove the `#include "charmm36-.../forcefield.itp"` line.
3. Replace `#include "charmm36-.../jz4_ffbonded.itp"` with the **contents** of
   that file (inline it).
4. Delete everything from `; Include water topology` to end-of-file.
5. Rename `[ moleculetype ]` from `Other` → the ligand resname (`JZ4`).
6. `#include "posre.itp"` → `#include "posre_jz4.itp"`.

> **2026.3 note — directive renames.** GROMACS 2026.3 renamed the top-level
> *type-definition* directives. The inlined `jz4_ffbonded.itp` contents (and any
> CGenFF GROMACS output) use the old names, so for this build rename:
> `[ bonds ]` → `[ bondtypes ]`, `[ angles ]` → `[ angletypes ]`,
> `[ dihedrals ]` → `[ dihedraltypes ]`, `[ pairs ]` → `[ pairtypes ]`.
> (The old names are now moleculetype-internal only — a top-level `[ bonds ]`
> fails with “Invalid order for directive bonds” in 2026.3.)

**5. System topology placement rules (the subtle part)**
In `topol.top`:
- The ligand parameter file (`jz4.prm`, with the new atom types + bonded
  parameters) must be `#include`d **after** the force-field include and
  **before** any `[ moleculetype ]`:
  ```
  #include "charmm36-.../forcefield.itp"
  #include "jz4.prm"

  [ moleculetype ]
  ; Name            nrexcl
  Protein_chain_A     3
  ```
  Rationale: bonded parameters can only be added for *known* atom types, so the
  FF (which defines the base types) must come first; and all FF parameters must
  be defined before any molecule definition.
- `#include "jz4_gmx.itp"` in the topology body (after the posre block, with the
  other molecule includes).
- Append the ligand coordinates to the system `.gro` (after the protein, before
  the box line) and update the atom count.
- `[ molecules ]` += `JZ4 1`.

**6. Ligand position restraints**
- Index group of ligand heavy atoms: `gmx make_ndx -f jz4.gro -o index_jz4.ndx`
  with expression `0 & ! a H*`.
- `gmx genrestr -f jz4.gro -o posre_jz4.itp -n index_jz4.ndx -fc 1000 1000 1000`
  (select the `JZ4` group when prompted).
- Atom numbers in `posre_jz4.itp` are **local** (1..N within the ligand
  moleculetype), **not** the global system atom numbers.

**7. This build**
CHARMM36/CHARMM36m is **not bundled** (only `charmm27.ff`). Install the
MacKerell-lab tarball (e.g. `charmm36-feb2026_cgenff-5.0.ff.tgz`) into `$GMXLIB`
or the working directory. The water `.itp` must be included from the FF
directory (2026.3 rule, above).

**8. Validate the result**
- Ligand heavy-atom RMSD vs. the bound pose (fit on the protein backbone):
  plateau ≈ 0.15 nm over 10 ns = good; drift/dissociation ⇒ suspect topology.
- Interaction-energy stability (see `01.8`).

### Carbohydrates / sugars

**When to use**: glycoproteins, free glycans, polysaccharides,
sugar-containing ligands/substrates. Carbohydrates are **not** organic
ligands — the `antechamber`/ACPYPE/CGenFF routes above do **not** apply to
sugars; they need the carbohydrate-specific **GLYCAM** parameter set.

**1. The GLYCAM route (the standard)**
- **GLYCAM-Web Carbohydrate Builder** (<https://glycam.org/cb/>) — assemble
  the glycan residue by residue: monosaccharide, glycosidic **linkage (α/β)**,
  ring type, anomeric configuration, derivatives. An **aglycone is added by
  default at the reducing end** and can be replaced with an anomeric residue
  (e.g. when the glycan is attached to a protein). For N-/O-glycosylated
  proteins use the **Glycoprotein Builder** (<https://glycam.org/pb/builder/>).
- Parameters: **GLYCAM06** (current revision **06j**, AMBER-based) — the
  standard carbohydrate FF. Amino-acid variants pair with AMBER 12SB
  (`GLYCAM_amino_06j_12SB`).
- **Server output is AMBER, not GROMACS**: the "Download Files For MD
  Simulation" archive contains `prmtop`/`parm7` (topology) + `inpcrd`/`rst7`
  (coordinates).

**2. Converting to GROMACS**
- `ant2gmx` is **not a command in this build (2026.3)** — do not plan around
  it.
- Convert the AMBER output to a GROMACS `.itp` + `.gro` with **ACPYPE** (the
  same tool as the AMBER ligand route above) or manually; alternatively
  **doGlycans** (Arantes et al. 2017, doi:10.1021/acs.jcim.7b00237) prepares
  carbohydrate structures for GROMACS directly.
- The result is a standard `[ moleculetype ]` `.itp` — integration is then
  identical to the ligand flow (see `00.4` "Ligand / custom molecule", `01.2`):
  `#include` the glycan `.itp` before `[ system ]`, add to `[ molecules ]`,
  append coordinates in matching order, regen `.tpr`.

**3. Force-field matching (critical)**
- GLYCAM06 is **AMBER-compatible** → pair with an AMBER protein FF (this build
  ships `amber14sb.ff`, `amber19sb.ff`, `amber99sb-ildn.ff`, …) + **TIP3P**.
  Do **not** mix GLYCAM with CHARMM (CGenFF) or OPLS parameter sets.
- Most glycans are **neutral** → no `genion` neutralization for the glycan
  itself; charged derivatives (sialic acid, sulfate, phosphate) contribute net
  charge and must be included in system neutralization (see `01.3`).

**4. Caveats**
- Glycan conformational flexibility; multiple glycoforms (mixture → separate
  moleculetypes, or a representative glycoform).
- Verify linkage/anomeric configuration of every residue in the builder; QM
  validation for new linkages/derivatives outside the GLYCAM parameter set.

> **Provenance**: GLYCAM-Web documentation (glycam.org, accessed 2026-09-16):
> Carbohydrate Builder (glycam.org/cb/) and Glycoprotein Builder
> (glycam.org/pb/builder/); "All Parameters" page (current set =
> `GLYCAM_06j`, amino variants for 12SB); Carbohydrate Builder help
> (simulation files = `prmtop`/`parm7` + `inpcrd`/`rst7`); Kirschner et al.,
> *GLYCAM06: a generalizable biomolecular force field. Carbohydrates*,
> J. Comput. Chem. 29:622–55 (2008), doi:10.1002/jcc.24428. `ant2gmx` absence
> and `amber14sb.ff`/`amber19sb.ff` presence verified against the local
> gromacs-rocm build (2026.3-dev-20260625).

### Inorganic species

**When to use**: buffer/metal ions, metalloproteins, phosphorylated
metabolites, coordination complexes.

**1. Standard inorganic ions already in the FF**
- Ion parameters are **bundled per FF directory**; the top-level `ions.itp`
  is a **`#error` stub in 2026.3** (like the water `.itp` files) — always
  include from the FF directory.
- **`amber14sb.ff` and `amber19sb.ff` ship per-water-model ion files**:
  `ions_opc.itp`, `ions_opc3.itp`, `ions_spc.itp`, `ions_spce.itp`,
  `ions_tip3p.itp`, `ions_tip4pew.itp`. **Pick the `ions_<model>.itp`
  matching your water model** (ion LJ parameters are water-model-specific).
  The sets are identical between the two FFs but differ per model:
  `ions_tip3p.itp` defines **62** types (`NA`, `CL`, `K`, `MG`, `CA`, `LI`,
  `ZN`, `FE`/`FE2`, `MN`, `AG`/`AG2`, `AL`, `BA`, `NH4`, `H3O`, …),
  `ions_opc.itp`/`ions_opc3.itp` **60** (no `NH4`/`H3O`), and
  `ions_spc.itp`/`ions_spce.itp`/`ions_tip4pew.itp` **57** (no `AG`/`CU1`/
  `NH4`/`H3O`/`TL`).
- Other FF directories ship a single plain `ions.itp` with a smaller set:
  `oplsaa.ff` — `MG CA LI NA K RB CS F CL BR I`; `charmm27.ff` — `OH NA MG K
  CS CA CL ZN`; `gromos54a7.ff` — `CU1 CU ZN MG CA NA CL`;
  `amber99sb-ildn.ff` — `IB+ CA CL NA MG K RB CS LI ZN`.
- Add standard ions with `gmx genion` (it "randomly replaces solvent
  molecules with monoatomic ions"; flags `-np`/`-pname`/`-pq`,
  `-nn`/`-nname`/`-nq`, `-conc`, `-[no]neutral`, `-rmin`, `-seed`; see
  `01.3`). Ion names are FF-specific — use the names defined in the ion set
  you included.

**2. Non-standard / exotic inorganic species** (specific coordination
complexes, unusual oxidation states, inorganic anions not in the FF):
- No standard parameters → **manual parameterization**: QM-derived partial
  charges, bonded terms from literature/experiment; document the source.
- **Multi-atom inorganic molecules** (sulfate, phosphate, nitrate,
  coordination complexes): `genion` only handles monoatomic ions — the
  build's own `genion` help recommends **`gmx insert-molecules`** for "larger
  ions, e.g. sulfate" (`-ci` input structure, `-nmol`/`-conc`, `-replace`,
  `-seed`, `-try`).
- **Metal coordination is hard**: d-electron/polarizability effects mean a
  fixed-charge additive FF is often inadequate. Options: restrained/
  position-restrained metal, dedicated ion models, polarizable FFs (Drude),
  or QM/MM for the active site. Flag as a case-by-case, high-uncertainty
  setup.

**3. Inorganic functional groups on organic molecules** (phosphate, sulfate,
nitrate — e.g. phosphorylated metabolites, nucleotides): standard residues
are covered by `pdb2gmx` (see `01.2`); check FF availability for the rest
(some are in CGenFF), and where absent, manual parameterization as in (2).

> **Provenance**: ion files, ion-type lists/counts, and `genion` /
> `insert-molecules` / `pdb2gmx` flags verified against the local gromacs-rocm
> build (2026.3-dev-20260625): `ls`/`grep` of
> `/usr/local/gromacs/share/gromacs/top/*.ff/ions*.itp`, `gmx genion -h`,
> `gmx insert-molecules -h`, `gmx pdb2gmx -h`.

## Protein prep decisions that affect the FF

- **Protonation states** (His, C-term, N-term): set before `pdb2gmx` (e.g.
  PROPKA at target pH). `pdb2gmx` uses its own H-addition (`-ignh`) if you let
  it.
- **Disulfides**: detected from the curated structure — `pdb2gmx` has **no**
  `-cys` flag in 2026.3.
- **Modified residues / metals**: may need manual topology or a different FF;
  check the FF's residue DB coverage.
- **Position restraints**: generated via `pdb2gmx -i posre.itp` (no `-bact`
  backbone-atom flag; `-[no]ss` is a boolean for interactive SS-bridge
  selection, not a sec-struct file).

## Choosing a setup (quick guide)

- **Standard protein in water** → AMBER (14SB/19SB + OPC/OPC3, or 99SB-ILDN +
  SPC/E) or OPLS (AA + SPC/E).
- **Membrane protein** → CHARMM (lipids + TIP3P) or POPC-specific sets; note
  this build ships `charmm27` (not CHARMM36), so CHARMM36 lipid parameters
  must be added manually; see `02.13`.
- **Ligand binding / FEP** → match the FF to your ligand-parameterization
  pipeline (AMBER+antechamber or CHARMM+CGenFF are the most mature).
- **Lipids / polymers / large soft matter** → Martini 3 (CG).
