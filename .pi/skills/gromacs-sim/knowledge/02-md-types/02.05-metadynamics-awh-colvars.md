# 02.05 — Metadynamics, AWH & Colvars (Adaptive Biasing)

**When to use**: enhance sampling by **adaptively** filling free-energy minima
along one or more collective variables (CVs) so the system escapes barriers —
**metadynamics** (PLUMED), **AWH** (native GROMACS), or **Colvars**.

## The three routes

### A. PLUMED (most flexible; metadynamics, umbrella, many biases)
- Enabled with `gmx mdrun -plumed plumed.dat`.
- Requires the PLUMED kernel: set **`PLUMED_KERNEL`** to the path of
  `libPlumedKernel.so` (usually `$plumed_prefix/lib/libPlumedKernel.so`).
- `plumed.dat` is a plain-text input describing CVs, biases (e.g.
  `METADYNAMICS`, `UMBRELLA`), and analysis.
- **Limitations of the GROMACS PLUMED interface**:
  - No interaction with GROMACS energy terms.
  - **Incompatible with thread-MPI** (errors if >1 thread-MPI rank).
  - Replica-exchange flavors not implemented.
- Analysis: PLUMED's own `WHAM`/`PLUMED2RESTRAINT`/`ANALYSIS` blocks.

### B. AWH — Adaptive Weighted Histogram (native)
- `awh = yes` in the MDP (yes/no enum, not an integer). **Requires a constant
  ensemble temperature** (`ensemble-temperature-setting = constant` +
  `ensemble-temperature = 300`).
- AWH flattens barriers along an RC by adding a history-dependent bias.
- The RC can be:
  - the **free-energy λ** directly (discrete), or
  - a **continuous CV** `ξ(x)` via a **pull coordinate** (must be
    `pull-coord1-type = external-potential` with
    `pull-coord1-potential-provider = awh`).
- **2026.3 AWH API** — each dimension needs an explicit coordinate provider:
  ```
  awh = yes
  awh-potential = convolved
  awh1-ndim = 1
  awh1-dim1-coord-provider = pull      ; or fep-lambda
  awh1-dim1-coord-index = 1            ; pull coordinate index
  awh1-dim1-force-constant = 1000      ; umbrella resolution (convolved)
  awh1-dim1-start = 0
  awh1-dim1-end = 2
  awh1-dim1-diffusion = 1e-5           ; rough estimate (warns if unset)
  ensemble-temperature-setting = constant
  ensemble-temperature = 300
  ```
  - `awh1-dimN-coord-provider = fep-lambda` uses the λ state as the RC
    (requires `awh-potential = umbrella`, `calc-lambda-neighbors = -1`).
  - The old `awh1-dim1-*` force-constant/start/end options still work;
    `awh1-ndim` + `awh1-dimN-coord-provider` + `awh1-dimN-coord-index` are
    the new required mapping.
- `awh-potential = convolved` (default; smooth bias from harmonic umbrellas)
  or `umbrella` (MC-sampled umbrella; **required** when using the λ dimension).
- **New 2026.3 AWH options**: `awh1-target` (`constant`/`cutoff`/
  `boltzmann`/`local-boltzmann`), `awh1-growth` + `awh1-growth-factor`
  (bias growth schedule), `awh1-error-init` (initial PMF error estimate),
  `awh1-histogram-tolerance`, `awh1-target-beta-scaling`,
  `awh1-target-cutoff`, `awh1-user-data`, `awh1-dimN-cover-diameter`,
  `awh1-share-group`.
- **Multi-sim sharing**: `awh-share-multisim = yes` + `mdrun -multidir` shares
  bias/PMF across compatible simulations (same `awh1-share-group`).
- Output: PMF + bias written to the `.edr` every `awh-nstout`; extract with
  `gmx awh` — **`-f` takes the `.edr`**, `-s` the `.tpr`, `-o` writes the PMF
  `.xvg`, `-fric` the friction `.xvg`.
- Not supported: `direction-periodic` pull geometry; time-dependent
  transformation coordinates.

### C. Colvars module (native; CVs + biases + free-energy profiles)
- Enabled via MDP options `colvars-active = yes` + `colvars-configfile =
  colvars.dat` (+ `colvars-seed`). (There is **no** `mdrun -colvars` flag in
  2026.3 — Colvars is MDP-only.)
- On-the-fly CV computation, external forces/biases (restraints, enhanced
  sampling), and free-energy profiles.
- `colvars.dat` is plain text; full docs in the Colvars project; **VMD's
  Colvars Dashboard** (VMD ≥ 1.9.4) can generate the file from templates.
- Cite the Colvars references printed in the log when using it.

## Choosing
- **Simple 1-D distance/dihedral PMF** → AWH (native, no extra install) or
  pull-code umbrella (`02.04`).
- **Metadynamics / complex multi-D CVs / many bias types** → PLUMED.
- **CVs with restraints + analysis, VMD workflow** → Colvars.

## Typical workflow (AWH example)
1. Standard prep + equilibration (`01.1–01.5`).
2. Define the CV (pull coordinate) + `awh = yes`, `awh1-*` parameters,
   `ensemble-temperature` constant.
3. Run (single long run, or `-multidir` with shared bias).
4. `gmx awh` → PMF ± uncertainty; check the bias has converged (flattened).

## MDP deltas vs. standard
- **AWH**: `awh = yes`, `awh-potential`, `awh1-ndim`, `awh1-dimN-*`,
  `awh-nstout`, `awh-seed`, `ensemble-temperature-setting = constant` +
  `ensemble-temperature`, plus the pull coordinate (with the 2026.3 pull API,
  see `02.04`).
- **PLUMED**: no MDP deltas — the bias lives in `plumed.dat` passed via
  `-plumed`.
- **Colvars**: `colvars-active = yes` + `colvars-configfile` (+ `colvars-seed`).
  (No `mdrun -colvars` flag in 2026.3.)

## Analysis
- AWH: `gmx awh`. PLUMED: PLUMED analysis blocks. Colvars: colvars output +
  its analysis tools.
- Verify the bias converged and the PMF is flat where expected.

## Pitfalls
- **PLUMED + thread-MPI** → hard error (PLUMED is incompatible with
  thread-MPI, i.e. more than 1 thread-MPI rank / `-ntmpi`); run with `-ntmpi 1`
  or regular MPI ranks. (This is **not** about OpenMP threads / `-ntomp`.)
- **AWH without a constant ensemble temperature** → not allowed.
- AWH umbrella dimension **requires** `awh-potential = umbrella`.
- Too-small metadynamics `dh`/bias deposition → over/under-counting; tune
  deposition + bias factor.
- CVs that don't capture the slow coordinate → enhanced sampling of the wrong
  thing.
- Forgetting `PLUMED_KERNEL` → PLUMED won't load.
