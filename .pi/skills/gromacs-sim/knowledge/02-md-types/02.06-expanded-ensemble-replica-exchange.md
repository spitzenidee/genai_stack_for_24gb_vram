# 02.06 — Expanded Ensemble / (Serial) Replica Exchange

**When to use**: sample **multiple thermodynamic states simultaneously** in a
single simulation — e.g. a range of **temperatures** (parallel/serial
tempering), a range of **free-energy λ** values, or both — by treating the
ensemble itself as a configuration variable. This is GROMACS's native
implementation of the **replica-exchange formalism, serialized** into one run.

## Core idea
- The probability of a state is
  `P(x, k) ∝ exp(−β_k U_k + g_k)`, where `β_k = 1/(k_B T_k)` is the k-th
  state's inverse temperature and `g_k` is a user weight.
- The simulation **alternates**:
  - **MD** steps to sample coordinates, and
  - **Monte-Carlo moves** to jump between thermodynamic states (changing the
    Hamiltonian: temperature and/or λ).
- Weights `g_k` are chosen (fixed or iteratively) to give each sub-ensemble
  roughly equal probability.

## Enabling
- `free-energy = expanded` (turns on expanded-ensemble mode; the different
  Hamiltonians are defined by the other free-energy options — λ arrays and/or
  a temperature list).
- States can vary **temperature**, **λ**, or **both**.
- **The old `lmc = yes` / `expanded = yes` options are gone** — the only way
  to enable it is `free-energy = expanded` (or `simulated-tempering = yes` for
  temperature-only tempering). The LMC options are only read when one of those
  is set.

## Key MDP options (2026.3 names — verified against the build)

| Option | Meaning |
|--------|---------|
| `free-energy = expanded` | Enable expanded ensemble. |
| `nstexpanded` | MD steps between attempted state-space moves (multiple of `nstcalcenergy`). |
| `lmc-stats` | Weight-update method: `no`, `metropolis-transition`, `barker-transition`, `minvar`, `wang-landau`, `weighted-wang-landau`. |
| `lmc-move` | State-space MC move: `no`, `metropolis`, `barker`, `gibbs`, `metropolized-gibbs`. **The old `lmc-mc-move` name is gone.** |
| `lmc-weights-equil` | When to stop weight updates: `no`, `yes`, `wl-delta`, `number-all-lambda`, `number-steps`, `number-samples`, `count-ratio`. |
| `lmc-seed` | Random seed for state-space MC. |
| `mc-temperature` | Temperature for MC accept/reject (default: first `ref-t` group). |
| `lmc-repeats` | Number of MC attempts per `nstexpanded` block (default 1). |
| `lmc-gibbsdelta` | integer; limits Gibbs sampling to states within ±N of the current one (default -1 = all states). |
| `lmc-forced-nstart` | Force the first N state moves to be accepted (debugging). |

### Weight-update methods (`lmc-stats`)
- `metropolis-transition` / `barker-transition`: update weights from
  accept/reject statistics.
- `wang-landau`: flatten the state occupancy (Wang-Landau in **state** space,
  not energy space).
- `minvar` (NOT `min-variance` — that value is rejected): emphasize states
  that still need sampling (weights are not the free energies).

### State-space moves (`lmc-move`)
- `metropolis` / `barker`: random up/down move + accept criterion.
- `gibbs` / `metropolized-gibbs`: choose the next state from the conditional
  weights (metropolized-gibbs excludes the current state; always ≥ as
  efficient as Gibbs).

## Typical workflow
1. Standard prep + equilibration at a reference state (`01.1–01.5`).
2. Define the **state space**: temperature list and/or λ grid (via the
   free-energy options).
3. Set `free-energy = expanded`, `nstexpanded`, and the MC/weight methods.
4. Run a long simulation; monitor **state occupancy** (should flatten over
   time) and per-state energies.
5. **Analyze**: reweight the sampled states to obtain free energies /
   properties at each state (Wang-Landau / ML weights; or standard
   reweighting). Check that neighboring states have adequate **overlap**.

## MDP deltas vs. standard
- `free-energy = expanded` + the expanded-ensemble block above (note the
  2026.3 names: `lmc-move`, `lmc-stats`, `lmc-weights-equil` — **not**
  `lmc-mc-move` / `min-variance`).
- A temperature list (for tempering) and/or λ arrays (for alchemical states).

## Analysis
- State-occupancy histogram (convergence → flat).
- Per-state energy / property averages; reweighting to target states.
- Overlap between neighboring states (exchange acceptance).

## Pitfalls
- **Insufficient overlap** between adjacent states → poor mixing, wrong
  weights.
- Too-large `nstexpanded` → rare state changes; too-small → MC overhead.
- Confusing `min-variance` weights with free energies (they're not).
- **Replica exchange / expanded ensemble is incompatible with GPU-resident
  update** on this stack (→ `01.7`).
- Forgetting that the PLUMED interface does **not** implement replica-exchange
  flavors (use the native expanded ensemble instead).
