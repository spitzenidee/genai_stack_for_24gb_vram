# 02.07 — Non-Equilibrium MD (NEMD) & Pulling

**When to use**: apply a **force or constraint** to drive the system out of
equilibrium — mechanical pulling (force/velocity ramp), **shear flow**
(rheology/viscosity), or COM dragging — and extract work → free energy via the
**Jarzynski equality**, or measure transport coefficients.

## The pull code (collective variables)
- The **pull code** applies forces/constraints on **collective pull
  coordinates** (reaction coordinates): distance, angle, or dihedral between
  **pull groups**. More complex CVs via the **transformation** pull
  coordinate.
- A pull group can belong to several pull coordinates; a coordinate can act on
  a single group + an absolute reference position.
- Distance can be in 1/2/3 dimensions or along a user-defined vector.

### Key MDP options (2026.3 API — the pull engine was rewritten)
| Option | Meaning |
|--------|---------|
| `pull = yes` | Enable the pull engine (yes/no). |
| `pull-ncoords` | Number of pull coordinates. |
| `pull-ngroups` | Number of pull groups. |
| `pull-groupN-name` | Group name (from the index file or default groups). |
| `pull-groupN-weights` | Optional per-atom weights for the group COM (multiplied with masses). |
| `pull-groupN-pbcatom` | PBC reference atom inside the group. |
| `pull-coordN-type` | `umbrella` (harmonic), `constraint` (rigid), `constant-force`, `flat-bottom`, `flat-bottom-high`, `external-potential`. **`umswitch` and the old `pull` (velocity/drag) types are gone.** |
| `pull-coordN-geometry` | `distance`, `direction`, `cylinder`, `direction-periodic`, `direction-relative`, `angle`, `dihedral`, `angle-axis`, `transformation`. |
| `pull-coordN-groups` | The group indices this coordinate acts on (e.g. `1 2`; group 1 is the reference). |
| `pull-coordN-dim` | Which dimensions are pulled — **booleans** (`yes no yes`; the `Y N Y` shorthand is also accepted), not `1 0 0`. |
| `pull-coordN-vec` | User-defined pull vector (for `direction` geometry). |
| `pull-coordN-origin` | Origin for angle/dihedral/transformation geometries. |
| `pull-coordN-init` | Reference value at t=0 (window center / constraint value). |
| `pull-coordN-rate` | Per-step change (velocity ramp). **Replaces `pull-coordN-increment`.** |
| `pull-coordN-k` | Spring constant (harmonic types). **Replaces `pull-coordN-force-constant`.** |
| `pull-coordN-start` | **yes/no** — add the starting COM distance to `pull-coordN-init`. |

### COM definition
`pull-groupN-weights` (per-atom relative weights) + `pull-groupN-pbcatom`
(PBC reference) control the group COM — choose to match the physical quantity
you want. **`pull-coordN-drag-coef` is gone** (no velocity-drag pull type
anymore).

## Non-equilibrium pulling → free energy (Jarzynski)
- Continuously changing a group distance **does work** → the system is out of
  equilibrium.
- The **Jarzynski equality** recovers the equilibrium ΔG between two distances
  from **many** non-equilibrium pulling trajectories:
  `ΔG_AB = −k_B T ⟨ e^{−β W_AB} ⟩_A`, where `W_AB` is the work done.
- Requires **many replicas** and (for convergence) not-too-fast pulling.

## Shear / rheology (see also `02.14`)
- Four ways to impose shear flow: constant group acceleration (mass-weighted
  force), velocity-driven, etc. Used to compute **viscosity**, friction, and
  shear-stress effects on conformation.

## Typical workflow (pulling → ΔG)
1. Standard prep + equilibration (`01.1–01.5`).
2. Define pull groups + a pull coordinate (`type = umbrella` with
   `pull-coordN-rate` = ramp rate, or `constraint` for a controlled path).
3. Run **many replicas** of the pulling protocol (same path, different seeds).
4. Collect the **work** `W` per replica (`gmx energy` pull terms).
5. Apply **Jarzynski** (or histogram/ML reweighting) → ΔG ± uncertainty.

## MDP deltas vs. standard
- Add the `pull = yes` + `pull-ncoords`/`pull-ngroups`/`pull-groupN-name` +
  `pull-coordN-*` block (2026.3 API). Keep thermostat standard (NVT typical
  for pulling; the work is the observable).

## Analysis
- `gmx energy` (pull work/force/distance terms), `gmx msd`/`distance` for the
  driven coordinate.
- Jarzynski / reweighting over replicas for ΔG.
- For shear: viscosity from the stress autocorrelation (Green–Kubo, `02.14`)
  or the linear shear-stress vs. rate.

## Pitfalls
- **Too-fast pulling** → large nonequilibrium work → Jarzynski needs an
  impractical number of replicas.
- Too few replicas → poor ⟨e^{−βW}⟩ estimate (a single large-W trajectory
  dominates).
- Wrong COM definition → wrong physical quantity.
- Forgetting the system is **out of equilibrium** — don't interpret instantaneous
  energies as equilibrium free energies.
- `direction-periodic` / time-dependent transformation coordinates are **not
  supported by AWH** (if combining with AWH, `02.05`).
