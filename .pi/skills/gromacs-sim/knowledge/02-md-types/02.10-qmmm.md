# 02.10 — QM/MM (Hybrid Quantum–Classical)

**When to use**: simulate processes where **electronic structure matters** —
chemistry with bond making/breaking, enzyme active sites, photochemistry,
redox — by treating a small **QM region** quantum-mechanically and the
surroundings classically (MM).

## Why not plain MD
- A classical force field assumes a **fixed covalent connectivity** (ground
  state). When connectivity changes (reactions, proton/electron transfer), an
  MM FF is invalid → use QM for the reactive region.

## GROMACS QM/MM: CP2K interface
- **Not available on this stack's build** (`CP2K support: disabled`). To use
  it, rebuild with `-DGMX_CP2K=ON` and a CP2K toolchain. The notes below apply
  once enabled.
- GROMACS drives the MM and interfaces with **CP2K** for the QM region.
- QM↔MM interactions use the **GEEP** approach (Laino et al.), a variant of
  **electrostatic embedding**:
  - Electron(QM) ↔ atom(MM) and nucleus(QM) ↔ atom(MM) **electrostatic**
    interactions are explicitly included.
  - The MM atoms' electrostatics polarize the QM region (embedding).
- **2026.3 API**: QMMM is a **module** named `qmmm-cp2k`, enabled with the
  flat MDP options below (the old `qmmm = yes` option is no longer usable —
  the build still recognizes it but hard-errors with `The QMMM integration
  you are trying to use is no longer supported`) plus
  `integrator = mimic` (MiMiC — microcanonical MD with QM/MM forces):
  ```
  integrator = mimic
  qmmm-cp2k-active = yes
  qmmm-cp2k-qmgroup = QM          ; index group with the QM atoms
  qmmm-cp2k-qmmethod = PBE        ; or PBE-D3 / BLYP / BLYP-D3 / PBE0 /
                                  ;   PBE0-D3 / B3LYP / B3LYP-D3 /
                                  ;   CAM-B3LYP / CAM-B3LYP-D3 / WB97X /
                                  ;   WB97X-D3 / INPUT (user CP2K input)
  qmmm-cp2k-qmfilenames = qminput ; base name for the CP2K input files
  qmmm-cp2k-qmcharge = 0          ; net charge of the QM region
  qmmm-cp2k-qmmultiplicity = 1    ; spin multiplicity of the QM region
  ```
  The QM atoms' MM charges are **nullified** (CP2K supplies their
  electrostatics). The QM region is specified by an index group.
  **Note**: in this build the `qmmm-cp2k-*` options still *parse* (the module
  is registered even with CP2K off), but activation fails at group validation
  — the options are only usable in a CP2K-enabled build.

## Setup outline
1. Standard prep of the full system (`01.1–01.3`).
2. **Define the QM region** (active-site residues + ligand + key waters) —
   small enough for the chosen QM method (DFT is typical), large enough to
   capture the chemistry.
3. Choose the **QM method/basis** in the CP2K input (method, basis set,
   dispersion, charge/spin of the QM region).
4. Set the `qmmm-cp2k-*` MDP options (`qmmm-cp2k-active = yes`,
   `qmmm-cp2k-qmgroup`, `qmmm-cp2k-qmmethod`, `qmmm-cp2k-qmcharge`,
   `qmmm-cp2k-qmmultiplicity`) + `integrator = mimic`; ensure the QM/MM
   **link atoms / capping** for bonds crossing the QM/MM boundary are handled
   (per CP2K/GROMACS convention).
5. **Equilibrate** the MM part (QM single points can be expensive; often
   equilibrate with MM first, then turn on QM).
6. Run; QM energies/forces are computed on the fly by CP2K.

## Practical notes
- **Cost**: QM/MM is far more expensive than MD — keep the QM region minimal.
- **Charge/spin** of the QM region must be set correctly (affects the physics).
- **Link atoms** at the QM/MM boundary cap dangling bonds — verify they're
  sensible.
- Check the log for the QM/MM setup summary and cite the method.

## MDP deltas vs. standard
- `integrator = mimic` + `qmmm-cp2k-active = yes` + the `qmmm-cp2k-*` options
  (QM region group, QM method, charge, multiplicity, input file base).
- Otherwise standard ensemble settings.

## Analysis
- MM observables as usual (`01.8`).
- QM observables (charges, orbitals, energies) come from **CP2K** output.
- Reaction coordinates / energies along the chemical step from the QM
  trajectory.

## Pitfalls
- QM region **too large** → intractable cost; **too small** → misses the
  chemistry.
- Wrong QM **charge/spin** → wrong physics.
- Ignoring **QM/MM boundary** capping → spurious forces.
- Equilibrating with QM on from the start (expensive) — equilibrate MM first.
- Not validating the QM method on a model system before the production run.
