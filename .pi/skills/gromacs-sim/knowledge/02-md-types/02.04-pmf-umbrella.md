# 02.04 — PMF & Umbrella Sampling

**When to use**: compute a **potential of mean force (PMF)** / free-energy
profile along a **reaction coordinate (RC)** — e.g. ligand pulling distance,
a dihedral, a group separation — by **umbrella sampling** (biasing windows
along the RC) and combining them.

## Core idea
- The PMF is the free energy as a function of a collective variable (CV/RC).
- Direct MD rarely crosses high barriers; **umbrella sampling** adds a
  harmonic bias centered at different RC values (windows), sampling each
  basin, then **WHAM/BAR** combines the biased samples into an unbiased PMF.

## GROMACS mean-force / PMF methods (and limits)

| Method | Acts on | Notes |
|--------|---------|-------|
| **Pull code** | group distances/angles/dihedrals (COM or absolute) | The native "pull" collective variables. **New API in 2026.3** (see below). |
| **AWH** | pull coordinates and/or the free-energy λ | Native adaptive biasing (see `02.05`). |
| **Free-energy code + harmonic bond/constraint** | single-atom distances | PMF via λ (see `02.03` machinery). |
| **PLUMED / Colvars** | arbitrary CVs | Most flexible (see `02.05`). |

## Umbrella sampling with the pull code (2026.3 API)

The pull engine was rewritten. **Old options `pull-coord` (int),
`pull-coord1-group1/2`, `pull-coord1-increment`, `pull-coord1-force-constant`,
`pull-coord1-flat-bottom`, and the `umswitch` type are gone.**

1. **Define groups and a pull coordinate** (distance between two groups):
   ```
   pull              = yes
   pull-ncoords      = 1
   pull-ngroups      = 2
   pull-group1-name  = Ligand
   pull-group2-name  = Protein
   pull-coord1-type      = umbrella          ; or constraint / constant-force /
                                             ;   flat-bottom / flat-bottom-high /
                                             ;   external-potential
   pull-coord1-geometry  = distance          ; or direction / cylinder / angle /
                                             ;   dihedral / transformation ...
   pull-coord1-groups    = 1 2               ; group indices (1 = reference)
   pull-coord1-dim       = no no yes         ; which dimensions are pulled
   pull-coord1-k         = 1000              ; force constant (kJ/mol/nm²)
   pull-coord1-init      = 1.5               ; reference value at t=0 (window center)
   pull-coord1-rate      = 0                 ; change rate (nm/ps); 0 = fixed
   ```
   - Geometry enum: `distance`, `direction`, `cylinder`, `direction-periodic`,
     `direction-relative`, `angle`, `dihedral`, `angle-axis`, `transformation`
     — **`COM` is no longer a geometry** (group COMs are implicit).
   - `pull-coord1-dim`: booleans — `yes`/`no` **or the `Y`/`N` shorthand**
     (both parse in 2026.3; e.g. `Y Y Y` = all three dims, `N N Y` = z only).
     Not `1 0 0`.
   - `pull-coord1-start = yes/no`: whether to add the starting COM distance to
     `pull-coord1-init` (it is a boolean, not a value).
   - `flat-bottom`/`flat-bottom-high`: harmonic above/below `pull-coord1-init`
     (no separate width option anymore).
   - For AWH, use `pull-coord1-type = external-potential` +
     `pull-coord1-potential-provider = awh` (see `02.05`).
2. **Windows**: for each window, set `pull-coord1-init` to the window center
   and `pull-coord1-k` (typ. 100–1000 kJ/mol/nm²). Run each window long
   enough for the RC to explore the basin.
3. **Combine** with `gmx wham` (or `gmx bar`) over the windows → PMF.
   **`gmx g_wham` is gone**; `gmx wham` takes file lists (`-ix`, `-if`, `-it`,
   `-is`, `-iiact`, `-tab`).

## Generating window starting configurations (SMD → windows → production)

For a distance RC, generate one starting configuration per window from an
SMD (steered-pulling) trajectory:

1. **Box first**: the minimum-image convention must hold at the **maximum**
   RC value, not just the initial configuration. Rule of thumb: the periodic
   image distance should be **≥ 2× the maximum RC value** (e.g. a **7.0 nm**
   dodecahedron for a 3.0 nm maximum COM distance; repo: 6.5 nm vectors for a
   3.0 nm RC). A dodecahedron saves volume/water vs a cube at the same
   periodic distance.
2. **SMD pull** to generate an RC trajectory (verified 2026.3, parses clean):
   ```
   pull              = yes
   pull-ncoords      = 1
   pull-ngroups      = 2
   pull-group1-name  = Chain_A
   pull-group2-name  = Chain_B
   pull-coord1-type      = umbrella      ; harmonic bias — a synonym for the
                                         ;   harmonic potential, NOT umbrella sampling
   pull-coord1-geometry  = distance
   pull-coord1-dim       = N N Y         ; repo pulls z only; set per RC
   pull-coord1-groups    = 1 2
   pull-coord1-start     = yes           ; initial value = computed COM distance
   pull-coord1-rate      = 0.01          ; nm/ps (= 10 nm/ns)
   pull-coord1-k         = 1000          ; kJ/mol/nm²
   ```
   (2026.3 notes: `title` and `optimize_fft` are obsolete — grompp ignores
   them; `fourier_nx/ny/nz` are still accepted but unnecessary.)
   **Rationale**: the spring rate is **not** the observed displacement — the
   spring builds force until the restoring forces are overcome. Check
   `pull_pullf.xvg` (spring force) and `pull_pullx.xvg` (RC time series).
   Repo: 500 ps pull.
3. **RC time series**: 2026.3 `gmx distance` accepts a **trajectory**
   directly (verified: `-f` takes xtc/trr/cpt/gro/…), so the one-shot form
   works — no per-frame splitting needed:
   ```bash
   gmx distance -s pull.tpr -f pull.xtc \
       -select 'com of group "Chain_A" plus com of group "Chain_B"' \
       -n index.ndx -oall dist.xvg
   ```
   (Single quotes around the selection, double quotes around index-group
   names. The pre-2026 pattern — `trjconv -sep` into per-frame `.gro` then
   `distance` per frame — is unnecessary in 2026.3.)
4. **Window extraction**: for each target ξ (repo: **28 windows over
   0.2–2.9 nm**, Δξ = 0.1 nm), pick the frame minimizing |d − ξ| and write
   it with `gmx trjconv -s pull.tpr -f pull.xtc -dump <t> -o window<i>.gro`.
5. **Per window**: equilibrate, then production. Two valid variants:
   - **Under-umbrella** (LiveCoMS repo): short **NPT equilibration (100 ps)**
     with the umbrella already anchored at the window's starting COM distance,
     then production. Use `pull-coord1-start = yes` (config was extracted at ξ,
     so the umbrella sits at ξ), `pull-coord1-rate = 0.0`, `pull-coord1-k`.
     (Source note: the repo *text* says production uses `start = no` +
     `pull-coord1-init`, but the repo's own `md_umbrella.mdp` uses
     `start = yes` without `init` — the mdp is adopted.)
   - **Bias-free first** (JPCB chignolin tutorial): run **NVT (100 ps) + NPT
     (500 ps)** per window with **no pull block** (position-restrained to the
     window structure), *then* start the umbrella production from the
     equilibrated state (`-c npt.gro -t npt.cpt`). This relaxes the structure
     before the bias is applied.
   Production length: long enough for the RC to explore the basin — the JPCB
   tutorial runs **50 ns per window** (26 windows, `nsteps = 25000000` at 2 fs);
   the LiveCoMS repo uses 10 ns. Match to your RC's relaxation time.
6. **Window spacing**: Δξ ≈ 0.1 nm typical; neighboring windows must
   overlap (WHAM validity — see Pitfalls).

## Umbrella / metadynamics via PLUMED or Colvars (preferred for complex CVs)
- For multi-D CVs or non-trivial RCs, use **PLUMED** (`gmx mdrun -plumed`) or
  **Colvars** (via MDP `colvars-active`/`colvars-configfile`; there is no
  `mdrun -colvars` flag) — see `02.05`. These give `UMBRELLA` bias +
  `WHAM`/`PLUMED2RESTRAINT` analysis natively.

## Entropic effects
- A PMF from a **distance** RC can miss entropic (configurational)
  contributions; ensure the RC captures the relevant physics, and consider
  broader CVs or longer sampling.

### Spherical volume-entropy correction (3-D COM distance RCs)
- For a **3-D COM distance** RC (two groups separating in solution, spherical
  symmetry), the 1-D WHAM histogram misses the **4πr² volume Jacobian** — the
  accessible spherical volume grows with r². Correct it:
  `ω(r) = ω_WHAM(r) + 2·k_B·T·ln(r)` (constants absorbed into the baseline).
  **Does NOT apply** to dihedral/angle RCs (no spherical volume there).
- **Bulk-plateau shift**: after the correction, subtract the mean of the
  plateau (r ≥ bulk cutoff — 2.0 nm in the repo) so the non-interacting limit
  is **0 kJ/mol**. (The WHAM zero-point convention itself — leftmost window =
  0, shifting is a systematic translation — is covered in Analysis above.)
- Worked example: r = 0.5 nm, T = 298.15 K → 2·k_B·T = 4.9579 kJ/mol,
  ln(0.5) = −0.6931 → correction ≈ **−3.44 kJ/mol**.
- (Source note: the repo *text* prints "2 k_BT ln(4)" — a typo; its equation
  and `correct_pmf.py` both use ln(r). Adopt ln(r).)
- Window starting configurations for such a PMF (SMD pull → frame extraction)
  → "Generating window starting configurations" (added by T-03).
- Reference system: methanol pair in water (Ghosh, Uddin & Choi, *J. Phys.
  Chem. B* 116:14254–14260, 2012).

## Typical workflow
1. Standard prep + equilibration (`01.1–01.5`) of the system.
2. Choose the **RC** and **window grid** (spacing ~0.1–0.2 nm for distances;
   overlapping basins).
3. Run **one simulation per window** (fixed bias center), in replicate.
   - `gmx mdrun -multidir` for the window tree.
4. **Analyze**: `gmx wham` / `gmx bar` (pull-code windows) or PLUMED/Colvars
   WHAM → PMF(x) ± uncertainty.
5. Verify **overlap** between neighboring windows (required for WHAM validity).

## MDP deltas vs. standard
- Add the `pull = yes` + `pull-ncoords`/`pull-ngroups`/`pull-groupN-name` +
  `pull-coordN-*` block (or use PLUMED/Colvars instead).
- Keep thermostat/barostat standard; often restrain the protein.

## Analysis
- `gmx wham` / `gmx bar`; `gmx energy` for the pull force/energy terms;
  PMF plot vs. RC.
- **PMF uncertainty**: `gmx wham` has a built-in Bayesian bootstrap —
  `-nBootstrap 100` (plus `-bs-method`/`-bs-tau`/`-bs-seed`) writes the
  per-bootstrap free energies to `-bsres` and profiles to `-bsprof`, giving an
  error bar on the PMF. Use with care (can underestimate if windows don't
  overlap well).
- Check window overlap + convergence (replicates).
- **WHAM zero-point convention**: `gmx wham` assigns the free energy of the
  **leftmost window** (lowest RC value) to 0; all other windows are relative
  to it. Shifting the whole curve to a more convenient zero (e.g. the bulk
  plateau) is a **systematic translation** — it does not change any ΔG.

## Pitfalls
- **No overlap** between windows → WHAM fails / wrong PMF.
- Force constant too weak → windows don't hold; too strong → poor sampling
  within a basin.
- RC that doesn't capture the slow coordinate → misleading PMF.
- Ignoring entropic contributions of a 1-D RC.
- Forgetting to **re-equilibrate** at each window center before production
  sampling of that window.
