# 02.09 — Simulated Annealing

**When to use**: drive the system through a **schedule of reference
temperatures** over time — e.g. heat then cool to escape local minima
(conformational search, crystal packing, finding a bound pose), or study
temperature-dependent behavior.

## Mechanism
- Annealing is implemented by **changing the reference temperature** of the
  temperature coupling over time. The actual system temperature relaxes toward
  the reference at the rate set by the **thermostat** — it does **not** jump
  instantaneously.
- **Important**: if you change the reference temperature **faster** than the
  thermostat can relax the system, the lag grows and you can **crash** when the
  difference becomes too large. Allow for the thermostat's relaxation time.
- Multiple groups can be annealed **independently** with arbitrary reference
  temperature schedules.

## Key MDP options (2026.3 API — the old `annealing-t`/`annealing-p`
pair-list options are gone)
| Option | Meaning |
|--------|---------|
| `annealing` | `no` / `single` / `periodic`, **one value per temperature group** (e.g. `single no` for 2 groups). |
| `annealing-npoints` | Number of annealing control points per group (0 = not annealed); entries must equal the number of `tc-grps`. |
| `annealing-time` | List of **times** (ps) of the control points (sum of `annealing-npoints`). |
| `annealing-temp` | List of **temperatures** (K) of the control points (sum of `annealing-npoints`). |
| `tcoupl` / `tau-t` / `tc-grps` | The underlying thermostat (controls relaxation rate). |

Example (one group, heat 300→500 K over 50 ps, hold, cool back):
```
annealing       = single
annealing-npoints = 4
annealing-time  = 0 50 150 200
annealing-temp  = 300 500 500 300
```

## Schedule design
- Define a series of **(time, temperature)** pairs; GROMACS interpolates the
  reference temperature between them.
- Keep each ramp **slower** than the thermostat relaxation (`tau-t`): a ramp
  over many × `tau-t` is safe.
- Typical: hold at T, ramp up, hold, ramp down, hold.

## Typical workflow
1. Standard prep + equilibration at the start temperature (`01.1–01.5`).
2. Set `annealing = single`, `annealing-npoints`, `annealing-time`,
   `annealing-temp`, and a thermostat with a sensible `tau-t`.
3. Run; monitor the **actual** temperature (should track the reference within
   the thermostat's lag).
4. Analyze the final (cooled) structure / trajectory as usual.

## MDP deltas vs. standard
- Add the `annealing*` options; keep a standard thermostat.

## Analysis
- Standard (`01.8`) on the resulting trajectory.
- Verify the system temperature followed the intended schedule (no large lag /
  no crash during ramps).

## Pitfalls
- **Ramp faster than thermostat relaxation** → temperature lag → crash.
- Forgetting the system temperature ≠ reference temperature instantaneously.
- Annealing a group with too-small a bath → `grompp` no longer errors (the
  old "fewer than 10% of the atoms" check is gone); it only prints the
  degrees-of-freedom NOTE. Merge small groups.
- Using annealing to "equilibrate" instead of proper NVT/NPT equilibration —
  it's a sampling/search tool, not a substitute for equilibration.
