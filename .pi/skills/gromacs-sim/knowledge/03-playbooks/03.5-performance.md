# 03.5 — Performance Tuning

How to get the most out of GROMACS, with this stack's GPU (gfx1100 / HIP /
RX 7900 XTX) front and center.

## The parallelization model

GROMACS parallelizes over:
1. **Intra-core SIMD** (SSE/AVX/AVX-512) — automatic.
2. **OpenMP threads** (`-ntomp`) — within a core group.
3. **MPI ranks** (`-ntmpi`) — across cores/nodes, via **domain
   decomposition**.
4. **GPU offload** — `nb`, `pme`, `bonded`, `update` tasks to the GPU.

The performance is dominated by the **non-bonded** (electrostatics + van der
Waals) work for most all-atom systems → putting `nb` (and `pme`) on the GPU is
the biggest win.

## GPU offload (this stack)

### Full offload (fastest for large all-atom systems)
```bash
gmx mdrun -ntmpi 1 -nb gpu -pme gpu -bonded gpu -update gpu -deffnm run
```
**Requirements** (all must hold):
- `-ntmpi 1` (single rank) — domain decomposition is incompatible.
- A **dynamical** integrator (`md`/`sd`), not `steep`/`cg`.
- System has classical bonded interactions (pure SETTLE water has none).

**Performance recommendation** (not a hard gate): `constraints = h-bonds`,
**not** `all-bonds`. With `all-bonds` on typical biomolecules the
coupled-constraint count exceeds the GPU LINCS topology-support limit
(`LincsGpu::isNumCoupledConstraintsSupported`) and the update **falls back to
CPU** — so `all-bonds` usually **disables** GPU-resident update. Prefer
`h-bonds` for speed. (For a 4 fs `dt` protocol needing `all-bonds`, expect a
CPU fallback for the update on typical systems.)

**`-update gpu` is NOT supported with** (2026.3, verified — any of these
forces the update/constraint step back to CPU, or the run refuses to start):
mass & constraints FEP, **virtual sites**, Ewald surface correction, replica
exchange, constraint pulling, orientation restraints, computational
electrophysiology, and triangle constraints (forbidden since 2024.4). The
biggest practical one is **virtual sites** — any system with a
`[ virtual_sites{,1,2,3,4} ]` section (e.g. TIP4P/2005, TIP5P, some lipids,
Martini) cannot use `-update gpu`. **`-pme gpu` / `-bonded gpu` additionally
require a dynamical integrator** (`md`/`sd`) — `steep`/`cg` are rejected (see
`01.4` for GPU-EM). For any of the above → CPU, or partial GPU (`-nb gpu`
only, which is the most permissive task).

**Detecting virtual sites before choosing a profile** (cheap, pre-mdrun):
`gmx dump` always prints empty `Virtual site N:` headers (each with an
`nr: 0` count), so a text `grep -i virtual` false-positives on every system.
Sum the `nr:` counts instead — `0` means no virtual sites:
```bash
gmx dump -s run.tpr 2>/dev/null | awk '/[Vv]irt.*site/{i=1;next} \
  i&&/nr:/{t=$0;gsub(/[^0-9]/,"",t);s+=t+0;i=0} END{print s+0}'
# result > 0 → no -update gpu (use gpu_safe / -nb gpu only)
```

### MTS — the biggest single-GPU lever (2026)
**Multiple Time Stepping** evaluates the expensive long-range PME mesh force
**less often** than the 2 fs base step. On this stack the PME/long-range work
is the single-GPU bottleneck, so MTS is one of the largest wins available —
combined with virtual sites it can nearly **double** throughput.

**MDP block** (exact keys, 2026.1 — `integrator = md` only):
```ini
mts                = yes
mts-levels         = 2                      ; only 2 is supported
mts-level2-forces  = longrange-nonbonded    ; PME mesh → the slow level
mts-level2-factor  = 2                      ; evaluate level-2 every 2nd step (4 fs)
```
- `mts-level2-forces` accepts: `longrange-nonbonded` (default; required when
  PME/Ewald is used), `nonbonded`, `pair`, `dihedral`, `angle`, `pull`, `awh`.
- Keep the level-2 interval `× dt` **≤ 4 fs** for the slow force (LJ/long-range
  stability limit).
- Combine with `constraints = h-bonds` + full offload for the best single-GPU
  ns/day. **Validate stability** (energy drift, T/P) before trusting it in
  production — MTS is not yet as battle-tested as the default path.

### Partial offload (when full isn't possible)
```bash
gmx mdrun -ntmpi 4 -ntomp 4 -nb gpu -pme gpu -deffnm run
```
- `nb` + `pme` on GPU, bonded/update on CPU, with MPI ranks.
- Good for FEP / expanded ensemble / small systems where `-ntmpi 1` isn't
  ideal.

### Confirming the GPU is engaged
- Read the **log**: look for `PP task will update and constrain coordinates on
  the GPU` and the GPU task assignments.
- `gmx --version | grep "HIP compiler flags"` must show
  `--offload-arch=gfx1100` (else the GPU code is for the wrong arch →
  segfaults; see `00.1`).
- GPU timing breakdowns come from the log's performance summary (there is no
  dedicated `GMX_ENABLE_GPU_TIMING` env var in this build).

### GPU selection / isolation (multi-GPU only — not used on this stack)
This stack has **one** GPU (gfx1100), so none of the below is needed; it is
documented for completeness if the stack is ever extended to multiple GPUs.
The variable names are **core GROMACS** (not CUDA-specific) and work in this
HIP build. (The CUDA-specific `CUDA_VISIBLE_DEVICES` is *not* the GROMACS
knob — use the `GMX_*` names below.)

| Variable | Purpose |
|----------|---------|
| `GMX_GPU_ID` | Select/restrict which detected GPUs are available (same syntax as `mdrun -gpu_id`, e.g. `GMX_GPU_ID=1` → GPU 1 only). Cannot combine with `-gpu_id`. |
| `GMX_GPU_PME_DECOMPOSITION` | PME decomposition across multiple GPUs; **requires a distributed GPU 3D-FFT library** (cuFFTMp/HeFFTe) — not applicable to a single-GPU HIP build. |
| `GMX_DISABLE_DIRECT_GPU_COMM` | Disable direct GPU communication in multi-rank runs (off if unset). |

On a single-GPU stack the task assignment is automatic; set nothing.

## CPU / MPI tuning

- **Match ranks to hardware**: don't over-partition a small system.
  - Small system (few 10⁴ atoms): `-ntmpi 1` + a few `-ntomp`.
  - Large system: more `-ntmpi` (one per core or per GPU+core group).
- **Domain decomposition** partitions the box into cells per rank. The
  **minimum cell size** is set by the largest charge/bonded group and the
  largest of `rvdw`/`rlist`/`rcoulomb`. A system too small for `n` ranks →
  `no domain decomposition for n ranks` error → reduce ranks or split large
  charge groups.
- **Dynamic load balancing** is on by default (rebalances cells to equalize
  work).
- **PME ranks**: for very large systems / multi-node, dedicate ranks to PME
  (`-npme <N>`, default -1 = guess).

## Benchmarking

```bash
gmx nonbonded-benchmark -o bench.csv -size 33 -nt 1 -simd auto
```
- **`gmx benchmark` is gone in 2026.3** — use `gmx nonbonded-benchmark`
  (sweeps non-bonded performance by system size / thread / SIMD / GPU combo).
  Key flags: `-o <.csv>` (output), `-size <multiplier>` (system = 3000 atoms × value), `-nt <threads>`,
  `-simd auto|no|4xm|2xmm`, `-coulomb ewald|reaction-field`, `-iter`,
  `-warmup`, `-all`.
- Read the **performance summary** at the end of every `mdrun` log (ns/day,
  per-task breakdown).
- Compare against the expected ns/day for your system size; a big drop ⇒ a
  feature forced a CPU fallback or a bad rank count.

## Common performance pitfalls

| Pitfall | Effect | Fix |
|---------|--------|-----|
| `constraints = all-bonds` | GPU-resident update unavailable | Use `h-bonds`. |
| `-ntmpi > 1` with `-update gpu` | Incompatible (DD) | Use `-ntmpi 1` for full offload. |
| FEP / expanded ensemble + GPU update | Incompatible | CPU or partial GPU. |
| Over-partitioning a small system | DD overhead, no gain | Fewer ranks. |
| `no domain decomposition for n ranks` | System too small / large charge group | Reduce ranks; split charge groups. |
| Writing full-precision (`.trr`) every frame | I/O bound | Use `.xtc`/`.tng` at 1–10 ps spacing. |
| Wrong GPU arch (not gfx1100) | Segfault on every mdrun | Rebuild with `GMX_HIP_TARGET_ARCH=gfx1100` (`00.1`). |
| AVX-512 auto-detect (Zen4) | Segfault | Force `GMX_SIMD=AVX2_256` (`00.1`). |

## Output-frequency performance
- **Never** write full-precision (`.trr`) every frame in production (I/O
  bound).
- `.xtc`/`.tng` every 1–10 ps (2 ps = 1000 steps at 2 fs is a safe default).
- Energy/log every 1–2 ps.
- Checkpoint every ~100 ps (protects long runs without I/O overhead).

## Stack-specific build notes (→ `00.1`)
- `GMX_HIP_TARGET_ARCH=gfx1100` (the standard `CMAKE_HIP_ARCHITECTURES` is
  silently ignored; wrong arch → segfault on every mdrun).
- `GMX_SIMD=AVX2_256` forced (AVX-512 auto-detect on Zen4 segfaults).
- Default **Makefiles** generator (Ninja incompatible with
  `-DGMX_BUILD_OWN_FFTW=ON`).
- **VkFFT** is the default on consumer RDNA.

## Tuning workflow (recommended)
1. Confirm GPU codegen (`gmx --version | grep "HIP compiler flags"`).
2. Try **full offload** (`-ntmpi 1 -nb gpu -pme gpu -bonded gpu -update gpu`)
   if the system allows (h-bonds, dynamical integrator, not FEP/RE).
3. Read the log's performance summary + GPU offload confirmation.
4. If full offload isn't allowed (FEP/RE/small system), use **partial offload**
   (`-nb gpu -pme gpu`) with tuned `-ntmpi`/`-ntomp`.
5. Run `gmx nonbonded-benchmark` to sanity-check throughput; compare to
   expectations.
6. For long runs, verify the checkpoint interval and that the log stays
   warning-free.
