# 01.9 — Phase 9: Troubleshooting & Validation

**Purpose**: map GROMACS error messages to causes and fixes. GROMACS errors are
descriptive — read them literally, then use this catalog.

> **Golden rule**: a crash is usually a *symptom*. The constraint/LINCS/1-4/PME
> messages are often the *first thing to fail* when the system is physically
> blowing up — fix the physics (prep, equilibration, dt, topology), not the
> algorithm.

## A. `pdb2gmx` errors

| Error | Cause | Fix |
|-------|-------|-----|
| `Residue 'XXX' not found in residue topology database` | FF lacks the residue, or name mismatch | Rename to FF convention, use a different FF, delete/model the residue. |
| `Long Bond (N-N = X nm)` / `missing atoms in molecule X` | Atoms missing earlier in the file | Check pdb2gmx output for which; add atoms or fix the side chain. |
| `Chain identifier 'X' is used in two non-sequential blocks` | A molecule inserted mid-chain | Reorder the file so chains are contiguous. |
| `WARNING: atom X is missing in residue XXX` | Missing H or name mismatch | Use `-ignh` to let pdb2gmx add H; or rename atoms. |
| `Atom X in residue YYY N was not found in rtp entry Z with M atoms` | Atom-name mismatch | Rename atoms to match the `.rtp`. |
| `No force fields found` | GROMACS data dirs not on path | Fix install / `GMXLIB` (see `00.1`). |

## B. `grompp` errors

| Error | Cause | Fix |
|-------|-------|-----|
| `Invalid order for directive xxx` | Section ordering violated / misplaced `#include` | Reorder directives; `[defaults]` first, once. |
| `Found a second defaults directive` | Duplicate `[ defaults ]` | Keep one. |
| `Atom index (n) in position_restraints out of bounds (1-N)` | Posre file in the wrong moleculetype | Move the posre `.itp` into the correct moleculetype. |
| `System has non-zero total charge` | Topology charge bug, or ions not added | Check cumulative charge column (should be integer per residue); add counter-ions. |
| `Incorrect number of parameters` | Incomplete bonded definition / mangled include | Fix the topology section. |
| `number of coordinates ... does not match topology` | Topology/coordinate atom count mismatch | Update `[ molecules ]` counts to match the `.gro`. |
| `Fatal error: No such moleculetype XXX` | Name in `[ molecules ]` has no moleculetype | Define the moleculetype (check `#ifdef`/`#include`). |
| `Number of degrees of freedom in T-Coupling group X is N` (NOTE; the old "fewer than 10% of the atoms" error is gone in 2026.3) | Tiny `tc-grps` group | Merge small groups into a larger bath. |
| `Invalid T coupling input: N groups, M ref-t values and M tau-t values` | `tc-grps` count ≠ `ref-t`/`tau-t` count (e.g. 2 groups but 1 value each) | Give one `ref-t` and one `tau-t` value **per** `tc-grps` group (e.g. `ref-t = 300 300`, `tau-t = 0.1 0.1`). |
| `The cut-off length is longer than half the shortest box vector` | Box too small for the cutoff (min-image violation) | Enlarge the box (≥ 2× cutoff) or reduce `rlist`/cutoff. |
| `Atom index (1) in bonds out of bounds (1-0)` | `[ settles ]` in the wrong molecule | Move the settles section. |
| `XXX non-matching atom names` | Topology order ≠ coordinate order | Reorder to match. |
| `Invalid line in X for atom N:` | Malformed `.gro`/`.pdb` line | Fix the coordinate file. |
| `An input file contains a line longer than 4095 characters` | Over-long line (often a wrapped include) | Split the line. |
| `Unknown left-hand 'xxx' in parameter file` | Option name removed/renamed in 2026.3 (e.g. `sc-r`, `free-energy-group`, `lmc-mc-move`, `tau-bfric`, `pull-coord`) | Look up the current name in `00.5`; **do not** hide it with `-maxwarn` (see below). |
| `Invalid enum 'xxx' for variable yyy, using 'zzz'` | Wrong value for an enum option (e.g. `tcoupl = v-rescale` is fine, but `tcoupl = V-rescale!` is not) | Use the value from the "Next time, use one of: ..." line in the error. |

> **`-maxwarn` pitfall (2026.3)**: `grompp -maxwarn N` downgrades *errors* —
> including **"Unknown left-hand" for removed/renamed options** — to warnings
> and proceeds. The resulting `.tpr` then runs with the **default** value of
> that option, not the value you wrote, and `mdrun` will happily run with
> silently-wrong physics. If you must use `-maxwarn` for a legitimate
> warning, verify every option you care about actually took effect (check the
> `grompp` log / the generated `.tpr` with `gmx dump`).

## C. `mdrun` errors

| Error | Cause | Fix |
|-------|-------|-----|
| `converged to within the available machine precision` | EM at a practical minimum (not a real error) | Accept if `Fmax`/`Epot` sane; else use double precision / different EM method. |
| `force on at least one atom is not finite` | Two atoms too close (clash) | Better structure / re-minimize; soft-core for CG (Martini). |
| `LINCS/SETTLE/SHAKE` warnings → crash | System **blowing up** (constraints fail first) | Diagnose per §E. |
| `1-4 (i,j) interaction not within cut-off! r=... Ignored` | Atoms flying apart (blowing up). **Do NOT increase the cutoff.** | Fix equilibration / `dt` / topology. |
| Simulation running but **no output** | Buffering, NaN, all `nst*`=0, or full disk | Set `GMX_LOG_BUFFER=0`; check for NaN; verify `nst*`; check disk. |
| `Can not do Conjugate Gradients with constraints` — no longer emitted (gone in 2026.3; `cg` + constraints is accepted) | `cg` EM + constraints | None — the combination is valid now. |
| `Pressure scaling more than 1%` | Box oscillation (resonance) | Better equilibration; larger `tau-p`; use C-rescale not PR when unequilibrated; smaller `dt`. |
| `Range checking error` | Blowing up | Better EM/equilibration/topology. |
| `X particles communicated to PME rank Y ... out of the domain decomposition cell` | Blowing up (atoms flying) | Diagnose per §E. |
| `One or more atoms moved too far between two domain decomposition steps` | Blowing up | Diagnose per §E. |
| `Some interactions seem to be assigned multiple times` | Blowing up / topology issue | Diagnose per §E. |
| `no domain decomposition for n ranks ... compatible ...` | Too many ranks for the box / large charge group | Reduce ranks; split large charge groups; check `-ntmpi`. |
| `Update task can not run on the GPU, because the following condition(s) were not satisfied: ...` (e.g. `Virtual sites are not supported`) | A GPU task is incompatible with the system (virtual sites, FEP, replica exchange, Ewald surface correction, constraint pulling, orientation restraints, triangle constraints) | Drop the offending GPU task: `-update cpu` (or `-nb gpu` only). This is a **startup** error (exits in seconds — cheap to retry). See KB `03.5` "GPU task-assignment compatibility" + the SKILL.md GPU-profile ladder. |

## D. "Blowing up" — what it is

A cascade: one atom gets an unacceptably large force → huge velocity/position
change → lands on another atom → even larger force → … → crash. The **first
symptom** is usually a LINCS/SHAKE/tabulated/1-4 warning (they fail first, not
because they're the cause).

**Common causes**:
- Insufficient energy minimization.
- Bad starting structure (steric clashes).
- `dt` too large (especially given the constraint choice).
- Free-energy particle insertion **without soft-core**.
- Inappropriate pressure coupling (e.g. Berendsen/PR before equilibrium).
- Inappropriate temperature coupling / groups.
- Position restraints to coordinates too different from the system.
- An isolated single water molecule.
- (Rare) an `mdrun` bug.

**Two basic solutions**: keep forces from getting that large (better prep), or
use a smaller `dt`.

## E. Diagnosing an unstable system (playbook)

1. **Capture frames**: set `nstxout` (or `nstxout-compressed`) to **1** and
   re-run from just before the crash; watch the trajectory to see which
   atoms/residues go unstable first.
2. **Simplify to isolate the cause**:
   - New box of solvent? Minimize/simulate a **single molecule** — is the
     topology inherently unstable, or is it clashes in the starting config?
   - Protein–ligand? Simulate the **protein alone** in solvent; if stable,
     simulate the **ligand in vacuo** to test its topology.
   - Remove "fancy" algorithms (especially before thorough equilibration).
3. **Monitor energy terms** with `gmx energy` — a spiking intramolecular term
   ⇒ improper bonded parameters.
4. **Don't ignore earlier warnings** (missing atoms in pdb2gmx, name mismatches
   in grompp) and don't paper over them with `grompp -maxwarn` (see §B —
   `-maxwarn` silently runs with *default* values for unknown options).
5. **Check MDP settings** for the FF/system: cutoffs, `nstlist`, temperature
   coupling. Wrong settings break the model physics even with a good starting
   config.
6. **No explicit solvent**: start equilibration with a **smaller dt** than
   production to help energy equipartition.

## F. Environment variables for debugging (→ `00.1`)
- `GMX_LOG_BUFFER=0` — unbuffered I/O (files always current).
- `GMX_SUPPRESS_DUMP` — stop pdb dumps during constraint failures.
- `GMX_MAXBACKUP=0` — fail if output exists (avoid clobbering).
- `GMX_TPI_DUMP=<E>` — dump low-energy configs (test-particle insertion).

## G. Validation & experimental features (→ `00.1`)
- Prefer **stable** features for reproducible work.
- **Experimental** features need env vars / build flags and are not for
  production.

## Decision shortcut
- **Crash in first few steps** → almost always prep (clashes, EM, dt, topology).
- **Crash after stable running** → check for a slowly growing energy term, a
  bad coupled group, or a box/cutoff issue under pressure.
- **No crash but wrong results** → check PBC/fit/index groups in analysis
  (`01.8`) and ensemble settings (`01.5`).
