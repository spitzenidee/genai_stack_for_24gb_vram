# 01.8 — Phase 8: Analysis

**Purpose**: extract quantitative results from the trajectory. Two sub-steps:
**(a)** clean/prepare the trajectory, **(b)** run the analysis tools.

## (a) Trajectory preparation

Most analysis needs a **PBC-fixed, fitted** trajectory.

1. **Build index groups** (`.ndx`):
   ```bash
   gmx make_ndx -f md.tpr -o index.ndx
   ```
   Group building is **interactive** (no `-select`/`-id` flags): at the prompt
   use the editor syntax — `r PRO` / `a CA` select by residue/atom name,
   `"Protein"` (quoted) copies an existing group, `!`/`&`/`|` combine groups.
   **Rename a group with `name <nr> <newname>`** (2026.3 form, e.g.
   `name 12 Gly1_CA`); the older `<nr> <newname>` form (e.g. `12 Gly1_CA`) is a
   **syntax error** in 2026.3. SELFLANG expressions are rejected here — they
   belong to `gmx select`.
   Default groups (System, Protein, Backbone, C-alpha, Water, ...) are
   auto-generated; add custom groups as needed. `gmx select` also uses SELFLANG.
2. **Fix PBC + fit** with `trjconv`:
   ```bash
   gmx trjconv -s md.tpr -f md.xtc -o clean.xtc \
       -pbc mol -fit rot+trans -center
   ```
   - `-pbc` enum: `none`/`mol`/`res`/`atom`/`nojump`/`cluster`/`whole` —
     `mol` keeps molecules whole across the box.
   - `-fit` enum: `none`/`rot+trans`/`rotxy+transxy`/`translation`/
     `transxy`/`progressive` — `rot+trans` removes global rotation +
     translation.
   - `-[no]center`: center the group in the box. (No `-surround` flag.)
   - Choose the fitting/centering group with `-n` (index group). (No
     `-fitref` flag.)
3. **Concatenate** multiple chunks: `gmx trjcat -f a.xtc b.xtc -o all.xtc`
   (no `-skip`/`-single` flags; use `-b`/`-e`/`-dt` for time selection).

> **Pitfall**: computing MSD/RMSD on a non-unwrapped trajectory gives
> garbage. RMSD/RMSF/Rg need unwrap (`-pbc`) **and** fit; MSD needs unwrap
> (`-pbc nojump`) **without** fit (see the MSD row).

## (b) Analysis tools (purpose → command)

### Global / stability
| Quantity | Command | Notes |
|----------|---------|-------|
| Energies, pressure, density, box | `gmx energy -f md.edr -o energy.xvg` | pick terms interactively. |
| RMSD (stability) | `gmx rms -s ref.pdb -f clean.xtc -o rmsd.xvg` | fit on backbone, RMSD on backbone or CA. |
| RMSF (flexibility, per-residue) | `gmx rmsf -s ref.pdb -f clean.xtc -o rmsf.xvg` | **`-[no]res`** averages the RMSF per residue (one value/residue) instead of per atom. |
| Radius of gyration | `gmx gyrate -s md.tpr -f clean.xtc -o rg.xvg` | overall radius of gyration (no `-res` flag; use `-sel`/`-fgroup` to change the group). |
| Secondary structure | `gmx dssp -s md.tpr -f clean.xtc -o dssp.dat` | per-frame DSSP; **`-o` writes `.dat`** (DSSP assignment list), `-num` writes the per-frame secondary-structure counts to `.xvg`. For **backbone H-bond-aware** assignment select the `MainChain+H` group (not bare `Backbone`) — the H atoms are needed for the H-bond term. |
| Time-series mean / error | `gmx analyze -f x.xvg -o avg.xvg` | average + (block) error estimate over one or more `.xvg` columns; `-av` average, `-ee` block-averaging error estimate, `-bw` bin width for the distribution (default 0.1); `-errbar <stddev|error|90>` adds error bars. Use for reporting mean ± SE of any plotted quantity. |
| Ramachandran | `gmx rama` / `gmx wheel` | |
| SASA | `gmx sasa` | solvent-accessible surface. |

> **RMSD is a degenerate metric** — a single value can correspond to multiple
> structural situations. A plateau does **not** mean convergence: a structure
> can keep changing internally at constant RMSD. **Never terminate a
> simulation on RMSD alone.**

### Dynamics / transport
| Quantity | Command | Notes |
|----------|---------|-------|
| MSD → diffusion | `gmx msd -s md.tpr -f msd_unwrapped.xtc -o msd.xvg -trestart 100` | Einstein relation; COM or atom. **MSD needs unwrapped but NOT fitted** — derive it directly from the production xtc (`gmx trjconv -s md.tpr -f md.xtc -pbc nojump -o msd_unwrapped.xtc`, System in/out); a per-frame-fitted trajectory inflates solvent D (~3× verified) and removes protein COM diffusion. **2026.3:** `-trestart` (default 10 ps) must be ≥ `-dt` (frame spacing); use `-trestart 100` on a 2 ps trajectory to bound memory; collective MSD (no `-mol`) for D; fit D from the curve (slope/6 over the linear regime, e.g. 100-2000 ps for water, 1000-5000 ps for a protein, in a 10 ns run); `-com` removed. |

### Conformational ensemble (PCA / FES)
Collective motions → principal components → 2-D free-energy surface. The
matrix, eigendecomposition, and **projection are all GROMACS-native** — no
external script is needed for them.

```bash
# 1. covariance matrix + eigendecomposition (covar -v writes the eigenvectors)
gmx covar -s md.tpr -f clean.xtc -n index.ndx -o eigenval.xvg -v eigenvectors.trr
# 2. analyze / project the eigenvectors (anaeig reads them via -v, not -in)
gmx anaeig -v eigenvectors.trr -s md.tpr -f clean.xtc -proj proj.xvg
```
- `gmx covar` flags: `-o` (eigenvalues, `.xvg`; the matrix is written by
  `-ascii` (ASCII) or `-xpm` (image)), `-v` (eigenvectors), `-av` (average
  structure), `-xpm` (matrix image); `-fit`/`-pbc` on by default.
- `gmx anaeig` flags: `-v` (eigenvector input file, from `covar -v`), `-eig`
  (eigenvalues), `-proj` (trajectory projected onto the eigenvectors, `.xvg`),
  `-2d` (2-D projection), `-nframes` (number of frames for the extremes
  output, default 2).
- **2-D histogram + FES** = `−k_BT·ln(P_i/P_max)` over the projected
  PC1×PC2 points. This is the only non-native step — ~10 lines of numpy in the
  Python sidecar (no Perl/MATLAB). `P_max` is the peak bin, so the FES minimum
  is 0.

> **Pitfall**: PCA is only as good as the trajectory prep — fit + unwrap
> first (step (a)), and use a long enough trajectory that the leading modes
> are sampled. The FES is a *projection* of the full PES; modes not captured
> by PC1/PC2 are missing.

### Interaction energies between groups

**When to use**: "how strongly does group A interact with group B?" (e.g.
ligand–protein). Computes the **short-range non-bonded** potential energy
(Coulomb + Lennard-Jones) between two index groups over a trajectory.
**Not** a binding energy or a free energy of any kind — it is a potential-energy
decomposition with no entropic contribution.

**Setup** (recipe):
1. Copy the production mdp and add the two groups:
   ```
   energygrps = Protein JZ4
   ```
   Groups must exist in the tpr — molecule-type names, or groups from an
   `-n` index file (verified 2026.3: `energygrps = G1 G2` with index groups
   grompp-parses clean).
2. Build a new tpr:
   ```bash
   gmx grompp -f ie.mdp -c npt.gro -t npt.cpt -p topol.top -n index.ndx -o ie.tpr
   ```
3. Recalculate the energies of the existing trajectory's configurations:
   ```bash
   gmx mdrun -deffnm ie -rerun md_0_10.xtc -nb cpu
   ```
   - `-rerun <traj>` re-evaluates the energy for each trajectory frame using
     the new tpr (no integration).
   - **`-nb cpu` is required**: multiple energy groups are **not supported on
     GPU** (manual: `energygrps` "not supported on GPUs"; `-nb` enum =
     auto/cpu/gpu).
4. Extract the cross terms with `gmx energy -f ie.edr -o interaction_energy.xvg`
   — pick `Coul-SR:A-B` and `LJ-SR:A-B` (A-B = first group vs. second).

**Caveats (must be stated)**:
- The per-term Coul/LJ decomposition has **no physical meaning** — it is
  force-field dependent.
- Only the *total* interaction energy may be meaningful, and only if the FF was
  parametrized to make it so (e.g. CHARMM targets QM solute–water interactions
  explicitly, which balances the terms).
- Report it as an interaction *energy*, never as a binding energy.

**Reference values** (repo, JZ4 2-propylphenol in T4 lysozyme, 10 ns, CHARMM):
Coul-SR −16.5 ± 10.0, LJ-SR −96.8 ± 7.4, total **−113.3 ± 12.4 kJ/mol**
(total = sum; combined SE = √(10² + 7.4²) ≈ 12.4 ✓).

## Using groups in analysis
- Every tool takes `-n` (index file / group selection). Groups are atom
  numbers (or molecule/angle/dihedral numbers where relevant). (No `-index`
  flag on analysis tools.)
- Build with `make_ndx` / `select` / `mk_angndx` (angles/dihedrals).

## Common pitfalls (→ `03.4`)
- Not unwrapping before MSD/RMSD (fit before RMSD/RMSF/Rg — but **not** before MSD; see the MSD row).
- Wrong index group (e.g. fitting on the whole system instead of backbone).
- Analyzing the raw `.xtc` instead of the cleaned one.
- Ignoring the `.log` warnings from the run.
- **xvg header lines break NR-based awk statistics**: xvg files begin with
  ~20-30 header lines; in awk statistics count data points sequentially
  (`dp++`) — never use NR (total line count) as the data index or range.
- Terminating a simulation because the RMSD plateaued (degenerate metric —
  see the note under Global/stability).
- **Using removed tool names** (`g_wham`, `dipole`, `solvation`, `nmat`, `pmat`,
  `rotinv`, `axias`, `fit`, `charge`, `ion2group`, `pmx`, `trjpos`, `do_*`
  aliases) — they no longer exist in 2026.3; see the tables above for the
  replacements.

## Validation criteria
- [ ] Clean trajectory produced (PBC + fit).
- [ ] Index groups correct (spot-check atom counts).
- [ ] Plausible results (RMSD stable, density correct, diffusion in expected
  range).
- [ ] Enough sampling (block/errbar analysis for error estimates).

## Outputs
Cleaned trajectory, index file, and a set of `.xvg`/plots + numerical results
with error estimates.
