# 01.1 — Phase 1: Structure Preparation & Validation

**Purpose**: turn a raw experimental structure (PDB) into a clean, complete,
physically sensible coordinate set ready for `pdb2gmx`.

## Inputs
- PDB file (or mmCIF) of the system of interest.
- Target pH (for protonation), force field choice (see `00.6`).

## Steps

1. **Curate the PDB** (external tools: PyMOL, ChimeraX, PDB2PQR):
   - Remove crystal water (unless explicitly studying it).
   - Fix **missing residues/atoms** (loops, side chains) — model or delete.
   - Resolve **alt-loc** records (pick one conformer).
   - Check **chains**: no interleaved/non-sequential chain blocks.
   - Handle **metals** (keep + coordinate, or delete), **disulfides**,
     **ligands/cofactors** (keep → parameterize per `00.6`; or delete).
2. **Set protonation states** at target pH (e.g. PROPKA). His states (HID/HIE/
   HIP), C-term (CTP/CTL), N-term (NTP/NTL).
3. **Run `pdb2gmx`**:
   ```bash
   gmx pdb2gmx -f protein.pdb -o protein.gro \
       -ff amber14sb -water opc \
       -i protein.posre.itp
   ```
   - `-i <.itp>`: writes the position-restraint file. `-[no]ss`: interactive SS
     bridge selection (boolean, takes no file). `-ignh`: let pdb2gmx add
     hydrogens (use when input H are wrong/absent).
   - **Disulfides** are detected from the curated structure (step 1) — there is
     no `-cys` flag. Detection threshold: Sγ–Sγ distance **2 Å ± 10%**
     (≈ 1.8–2.2 Å), per the FF's `specbond.dat`. For an
     **intermolecular** disulfide (bridge between two chains), the chains must
     be in one moleculetype — use `-[no]merge` (`no`/`all`/`interactive`) to
     merge chains into a single `[moleculetype]` after termini are added.
   - **Chain termini / capping**: `-[no]ter` selects termini interactively;
     the **default is ionized** (N-term NH3⁺, C-term COO⁻). For **neutral
     caps** (N-acetyl `ACE` / N-methyl-amide `NME`), supply them as **named
     residues in the input PDB** — `pdb2gmx` recognizes `ACE`/`NME` directly
     (build the cap atoms in the PDB with any editor; AMBER FFs instead use
     `N`/`C`-prefixed terminal residue names, which are incompatible with
     `-ter`).
   - TM-helix orientation is set during curation or with
     `editconf` — there is no `-membrane` flag.
   - Outputs: `protein.gro`, `protein.top`, `protein.itp`, `protein.posre.itp`.
4. **Validate the output**:
   - Read the **cumulative charge** comment column in the `.top` atom listing —
     must be an **integer after every residue**. Non-integer ⇒ topology bug.
   - Confirm no `WARNING: atom X is missing in residue ...`.
   - Confirm atom count matches the input (plus added H).

## Key tools
`pdb2gmx` (see `00.2`), external: PyMOL/ChimeraX/PDB2PQR/PROPKA.

## Common errors (→ `01.9`)
- `Residue 'XXX' not found in residue topology database` — FF lacks the
  residue, or name mismatch. Fix the name, use a different FF, or delete/model.
- `Long Bond (N-N = X nm)` / `missing atoms in molecule X` — atoms missing earlier in the file.
- `Chain identifier 'X' is used in two non-sequential blocks` — a molecule
  inserted mid-chain; reorder.
- `Atom X in residue YYY N was not found in rtp entry Z with M atoms` — atom-name mismatch; rename.
- `No force fields found` — GROMACS data dirs not on path (install issue).

## Validation criteria (gate to Phase 2)
- [ ] No missing-atom warnings from `pdb2gmx`.
- [ ] Cumulative charge integer per residue.
- [ ] Atom names consistent with the FF `.rtp`.
- [ ] Protonation + disulfides + metals decided and documented.

## Outputs
`protein.gro`, `protein.top`, `protein.itp`, `protein.posre.itp`, and a written
record of prep decisions (pH, disulfides, deletions).
