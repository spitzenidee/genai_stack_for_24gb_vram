# 01.2 — Phase 2: Topology & Force Field Assembly

**Purpose**: assemble a complete, correct topology (`.top` + included `.itp`)
for the whole system (protein + ligands + later water/ions), with restraints in
place.

## Inputs
- `protein.gro` / `protein.top` / `protein.itp` from Phase 1.
- Ligand `.itp`/`.gro` (parameterized, `00.6`) if present.
- Position-restraint policy (default: backbone + heavy atoms restrained).

## Steps

1. **Inspect the `pdb2gmx` topology**:
   - Confirm `[ defaults ]` first, moleculetype sub-section order, `nrexcl`.
   - Check the **charge-group** layout (large charged groups hurt scaling).
   - Verify 1-4 handling (`[ pairs ]` when `nrexcl=3`).
2. **Add ligands** (if any):
   - `#include "ligand.itp"` before `[ system ]`.
   - Add `LIG 1` to `[ molecules ]`; append ligand atoms to the coordinate file
     in the matching order.
3. **Position restraints** (for equilibration; usually off in production):
   ```bash
   gmx genrestr -f protein.gro -o protein.posre.itp -fc 1000
   ```
   - Default `fc = 1000 kJ/mol/nm²`. Staged relaxation uses lower values
     (see `02.02`).
   - Include the posre `.itp` **inside the correct moleculetype**.
4. **Assemble the final `.top`**:
   ```
   #include "amber14sb.ff/forcefield.itp"
   #include "protein.itp"
   #include "ligand.itp"
   ; #include "protein.posre.itp"   ; enable for equilibration
   [ system ]
   Protein + ligand in water
   [ molecules ]
   Protein  1
   LIG      1
   ; SOL / NA / CL added after solvation (Phase 3)
   ```
   - **`[ system ]` is required** (2026.3): `grompp` fails fatally if
     `[ molecules ]` appears without a preceding `[ system ]` line.
   - Water/ion `.itp` includes must come **from the FF directory** in 2026.3
     (e.g. `#include "oplsaa.ff/spce.itp"`), not top-level (`spc.itp` etc. are
     `#error` stubs now). See `00.6`.
   - **Section headers are written** (2026.3, verified): `pdb2gmx` writes the
     standard `[ moleculetype ]` + `[ atoms ]` headers — the name line
     (`Protein_chain_A 3`) sits between `[ moleculetype ]` and `[ atoms ]`,
     and the atom lines run from `[ atoms ]` until `[ bonds ]`. Scripts that
     parse the topology may anchor on those headers.
5. **Sanity checks**:
   - Every `[ molecules ]` name has a moleculetype (with `[ moleculetype ]`/
     `[ atoms ]` headers — see above).
   - `[ molecules ]` order == coordinate-file order.
   - Total charge integer (after ions, see Phase 3).

## Key MDP-relevant topology facts
- `nrexcl` and `[ defaults ]` scaling must match the FF.
- `constraints = h-bonds` (recommended) vs `all-bonds` — h-bonds keeps
  GPU-resident update available (this stack).
- Charge-group size affects minimum DD cell size (parallel scaling).

## Common errors (→ `01.9`)
- `Invalid order for directive xxx` — section ordering / misplaced `#include`.
- `Found a second defaults directive` — duplicate `[ defaults ]`.
- `Atom index (n) in position_restraints out of bounds (1-N)` — posre in wrong
  moleculetype.
- `Fatal error: No such moleculetype XXX` — missing moleculetype.
- `XXX non-matching atom names` — topology/coordinate order mismatch.
- `System has non-zero total charge` — topology charge bug (check cumulative
  charge column) or ions not yet added.

## Validation criteria (gate to Phase 3)
- [ ] Topology parses in `grompp` (test with a minimal MDP).
- [ ] Charge integer per residue; total charge as expected.
- [ ] Ligand included and order-consistent.
- [ ] Posre file present and correctly placed (if restraining).

## Outputs
Final `.top` (pre-solvation), posre `.itp`, and a documented topology layout.
