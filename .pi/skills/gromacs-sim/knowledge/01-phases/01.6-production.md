# 01.6 — Phase 6: Production MD

**Purpose**: run the actual sampling at the target ensemble (usually NPT),
generating the trajectory to be analyzed.

## Inputs
- End-of-NPT structure (`npt.gro` or last NPT frame) + `.top`.
- `md.mdp` (production).
- (Position restraints **off** unless the protocol requires them — `02.02`.)

## Steps

1. **`md.mdp`** (see template `03.2`):
   ```
   integrator  = md
   nsteps      = 5000000        ; 10 ns at 2 fs
   dt          = 0.002
   tcoupl      = v-rescale
   tau-t       = 0.1 0.1
   ref-t       = 300 300
   tc-grps     = Protein Non-Protein
   pcoupl      = C-rescale
   pcoupltype  = isotropic
   tau-p       = 2.0
   compressibility = 4.5e-5
   ref-p       = 1.0
   constraints = h-bonds
   nstcomm     = 1000
   ; output
   nstxout-compressed = 1000    ; write xtc every 2 ps
   nstenergy   = 1000
   nstlog      = 1000
   nstcalcenergy = 1
   ; checkpoint interval: mdrun -cpt <minutes> (nstcheckpoint is obsolete in 2026.3)
   ```
2. **Preprocess + run** (no posre for plain production):
   ```bash
   gmx grompp -f md.mdp -c npt.gro -p topol.top -o md.tpr
   gmx mdrun -deffnm md -cpt 0.1 -ntmpi 1 -nb gpu -pme gpu -bonded gpu -update gpu
   ```
   (`-cpt` is in **minutes**; `0.1` ≈ checkpoint every 100 ps at 2 fs.)
   (GPU flags per `03.5`; confirm the log says update/constrain **on the GPU**.)

## Key MDP options

| Option | Recommended | Rationale |
|--------|-------------|-----------|
| `integrator` | `md` (leap-frog) | Default, robust. Use `md-vv` for Nose-Hoover/MTTK. |
| `dt` | `0.002` (2 fs) | Standard with `h-bonds` constraints + SETTLE. Use 1 fs if unconstrained or sensitive. |
| `nsteps` | per target length | `nsteps × dt` = total time. |
| `tcoupl`/`pcoupl` | `v-rescale` / `C-rescale` | Correct ensembles (2026 guidance). |
| `nstxout-compressed` | 1000 | xtc every 2 ps (enough for most analysis). |
| `nstenergy`/`nstlog` | 1000 | energy/log every 2 ps. |
| `nstcalcenergy` | 1 | compute energy every step (needed for coupling). |
| checkpoint interval | `mdrun -cpt 0.1` (minutes) | checkpoint every 100 ps → never lose >100 ps. `nstcheckpoint` in the MDP is obsolete (silently ignored) in 2026.3. |
| `nstcomm` | 1000 | remove COM velocity periodically. |
| `cutoff-scheme` | `Verlet` | default; pair-list buffering. |
| **MTS** (optional) | `mts=yes`, `mts-level2-forces=longrange-nonbonded`, `mts-level2-factor=2` | evaluate the PME mesh force every 2nd step (≤4 fs) → near-2× single-GPU throughput. Full block + caveats in `03.5`. Validate stability before production. |

## Monitoring during the run

- **Energy drift**: for a true NVE check, run a short NVE and confirm total
  energy drift is small (kJ/mol/ps). In NPT, monitor total energy stability.
- **Read the `.log`** at the end (and periodically for long runs):
  - Performance summary, any warnings.
  - GPU offload confirmation.
- **`.edr`** via `gmx energy`: potential/kinetic/total energy, pressure,
  temperature, box volume, density.

## Output frequency guidance
- **Never** write full-precision (`.trr`) every frame in production (I/O bound).
- `.xtc`/`.tng` every 1–10 ps is typical; 2 ps (1000 steps at 2 fs) is a safe
  default.
- Energy/log every 1–2 ps.
- **TNG in 2026.3**: `.tng` is a first-class trajectory format that can carry
  coordinates, velocities, forces, and/or energies (controlled by the
  `nstxout`/`nstvout`/`nstfout`/`nstenergy` options and their compression
  settings). `mdrun -x` accepts `.tng` ("tng format or portable xdr format");
  the **default compressed output remains `.xtc`** (`traj_comp.xtc`), so to get
  `.tng` name the file with a `.tng` extension. Read back with
  `gmx dump -f traj.tng` / `gmx check -f traj.tng`.

## Common errors (→ `01.9`)
- `1-4 (i,j) interaction not within cut-off! r=... Ignored` — system **blowing up** (large
  velocities). Do **not** increase the cutoff; fix equilibration / `dt` /
  topology.
- `LINCS/SETTLE/SHAKE` warnings then crash — blowing up (see `03.4`).
- `Pressure scaling more than 1%` — box oscillation (see `01.5`).
- `Range checking error` / `X particles communicated to PME rank Y ...` —
  blowing up.
- Simulation running but **no output** — buffering, NaN, all `nst*`=0, or full
  disk (see `01.9`).

## Validation criteria (gate to Phase 8 / analysis)
- [ ] Run completed `nsteps` (or intentionally stopped + checkpointed).
- [ ] Energy drift acceptable; no sustained spikes.
- [ ] Temperature/pressure stable at targets.
- [ ] No constraint/range-check warnings in the log.
- [ ] Trajectory + energy files present and non-trivial size.

## Outputs
`md.tpr`, `md.xtc`/`md.tng`, `md.edr`, `md.log`, `state.cpt`. Proceed to
analysis (`01.8`) or restart/extend (`01.7`).
