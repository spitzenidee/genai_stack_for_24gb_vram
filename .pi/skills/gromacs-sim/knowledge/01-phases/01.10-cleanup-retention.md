# 01.10 — Phase 10: Cleanup & Retention

**Purpose**: deterministically dispose of transient artifacts after the
analysis phase, so a finished project keeps only what is permanent. This is
the last phase of the workflow; a simulation is not done until it passes.

## The `#name.N#` auto-backup mechanism (root cause of bloat)

Every GROMACS tool that is asked to write an output file that **already
exists** renames the existing file to `#name.1#`, `#name.2#`, … (incrementing
the lowest free suffix) and writes the new output under the plain name.
This is by design (it protects previous results) — but it means **every
re-run of a tool leaves a full stale copy behind**.

Typical bloat source: re-running the analysis suite (e.g. while fixing a
gate bug). Each run re-writes `clean.xtc`, `step1.xtc`, `msd_unwrapped.xtc`, every
`.xvg`, `index.ndx` — so N suite runs leave N−1 stale copies of each
multi-hundred-MB trajectory.

**Reference case (lysozyme, 10 ns, 34 k atoms):** the analysis suite ran 5
times → 52 stale `#*.N#` files totaling **5.03 GB — 71 % of the 6.6 GB
project**. Total cleanup (58 files incl. checkpoints + derived
intermediates) freed 5.32 GB (81 % of the project). After cleanup: ~1.3 GB.

## Retention policy

| Class | Examples | Keep? | Rationale |
|-------|----------|-------|-----------|
| Source trajectory | `06_production/md.xtc` | **Yes, forever** | The actual data; everything else derives from it. |
| Analysis trajectory | `07_analysis/clean.xtc` | **Yes** (policy) | Re-analysis then needs no `trjconv` re-run on the full trajectory. |
| Results | 10 `.xvg` + 10 `.png` + `REPORT.md`, `index.ndx`, `hbond.ndx` | **Yes, forever** | The outputs of the work. |
| Reproducibility | all `.mdp`/`.top`/`.tpr`/`.gro`, `input/`, `state.json`, `RUNLOG.md`, logs | **Yes, forever** | Small; enables re-runs, audits, bug RCA. |
| GROMACS auto-backups | `#*.N#` anywhere | **No** | Stale copies of current outputs; the plain-named file is the latest. |
| Checkpoints | `*.cpt` (e.g. `md.cpt`, `md_prev.cpt`, `nvt.cpt`, `npt.cpt`) | **No** (after completion) | Only useful to resume an *interrupted* run (`-cpi`). A completed run never needs them. |
| Derived intermediates | `07_analysis/step1.xtc` (PBC step), `07_analysis/msd_unwrapped.xtc` (unwrapped, no fit) | **No** | Regenerable from `md.xtc` (below). |
| Gray zone | `05_equil/*.xtc` (~36 MB), `04_em/em.log` (~5 MB), `07_analysis/md.gro` (~2 MB) | **Yes** (default) | Small; diagnostic value (equilibration behavior, EM convergence history). |

Rules of thumb:

- **Never delete the source trajectory** (`md.xtc`) — it is the only
  unrecoverable artifact (re-running 10 ns costs days of GPU time).
- **Delete only by explicit whitelist** (the three transient classes above).
  No size-based or pattern-glob "clean up big files" heuristics.
- **Checkpoints are resume-only.** Once the run reached its final step,
  `*.cpt` files are dead weight.
- Cleanup is **idempotent**: re-running on a clean project frees 0 bytes.
  After any re-analysis (which re-creates `#*.N#` files), re-run cleanup.

## Regeneration paths (if a kept file is ever lost)

- `step1.xtc` from `md.xtc`: `gmx trjconv -s md.tpr -f md.xtc -n index.ndx
  -pbc mol -o step1.xtc` (group `0`).
- `clean.xtc` from `step1.xtc`: `gmx trjconv -s md.tpr -f step1.xtc
  -n index.ndx -fit rot+trans -center -o clean.xtc` (fit Backbone, center
  Protein, output System). ~10 min for a 10 ns / 34 k-atom system.
- `msd_unwrapped.xtc` from `md.xtc`: `gmx trjconv -s md.tpr -f md.xtc -pbc nojump -o msd_unwrapped.xtc` (all-atoms group; **no fit** — MSD needs unwrapped, not fitted; see the 01.8 MSD row).
- Any `.xvg`: re-run the single suite item (KB 01.8).

## Validation criteria

- Zero `#*.N#` files remain in the project.
- `md.xtc`, `clean.xtc`, `REPORT.md` all still present and non-empty.
- Project size matches expectation (lysozyme reference: ~1.3 GB after
  cleanup).
- `cleanup_report.txt` written at the project root; `RUNLOG.md` records
  files/bytes freed and before/after size.

## Outputs

`cleanup_report.txt` (deletion list + sizes + result), updated
`state.json` (`gates.cleanup`), `RUNLOG.md` entry.
