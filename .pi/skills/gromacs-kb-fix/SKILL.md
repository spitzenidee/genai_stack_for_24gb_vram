# GROMACS KB Fix

Apply the fixer half of the audit→fix contract: fix the open `### I-NN`
entries in `.pi/skills/gromacs-sim/knowledge/issues_kb.md`. The hard rules below are the
contract; the audit skill (`gromacs-kb-audit`) owns all deterministic
machinery, which you reuse, never duplicate:
- Probe suite (regression + build snapshot):
  `.pi/skills/gromacs-kb-audit/scripts/probe_suite.sh`
- Targeted-probe assets (verified minimal system):
  `.pi/skills/gromacs-kb-audit/assets/` (`base.mdp`, `tmin.gro`,
  `tmin.top`, plus the trap notes in its `README.md`)
- Probe patterns & grading rubric: the audit skill's SKILL.md, sections
  "Reading probe output" and "Step 3 — Map claims to the snapshot".

## Paths

| What | Where |
|---|---|
| Stack root | `$STACK_ROOT` = `/home/<user>/docker/genai_stack` (a git repo) |
| Knowledge base | `.pi/skills/gromacs-sim/knowledge/` — content files (00–03) + `README.md` + `issues_kb.md` |
| Issues log | `.pi/skills/gromacs-sim/knowledge/issues_kb.md` — your work list + the only log you write |
| Container access | transient, CPU-only (no GPU devices ever passed): `docker run --rm -w /work -v $STACK_ROOT/gromacs/work/kb-audit:/work gromacs-hip-gfx1100:latest <cmd>` — works in any stack mode, at any time; no running container needed |
| Session dir | `gromacs/work/kb-audit/` (= `/work` in the transient container) — shared with the audit skill; wiped and regenerated by the suite at the start of every suite run; no cross-run persistence |

## Hard rules

1. **Open issues only.** Your work list is exactly the `### I-NN` entries
   without a RESOLVED/FIXED marker. No new issues, no adjacent
   "improvements", no reformatting, no prose polishing, no touching
   Verified-OK lists or Notes sections.
2. **No drift.** `gmx --version` must match the Gold-standard header
   (step 2); mismatch → stop, hand back to audit.
3. **No probe, no edit.** Every issue gets the step-3 preflight (locate →
   re-probe → verify fix text) against the live build before any edit.
4. **Verify the fix text too.** Every option name, value, enum, flag, tool
   name, or file the fix's NEW text introduces must be confirmed against the
   build before applying. Recommended fixes are hypotheses — 4 of 63
   historical issues carried wrong fix text (I-15, I-39, I-44, I-54).
5. **Minimal diff.** Apply the verified fix to every file in the issue's
   `Files:` list, one issue at a time, in number order. Corrected variant
   (rule 4) → dated **Fix deviation** note; the audit's original text is
   never rewritten.
6. **Hand back only when UNFIXABLE.** An issue stays open and goes to the
   auditor only if: **UNVERIFIABLE** (needs GPU or a long run),
   **UNRESOLVABLE** (the correct text cannot be derived from the build
   within targeted-probe scope), or **CONTESTED** (conflicts with another
   open issue or a Verified-OK entry). A false positive is **not** a
   handback — you close it with the disproving evidence.
7. **Regression gate.** After all fixes: re-run the full probe suite
   (step 5). Any NEW parse signal (unknown/invalid/obsolete) → revert that
   issue's edits, leave it open, note it.
8. **Evidence-based close.** `✅ RESOLVED (date)` on an issue header line
   only when the fix-pass section carries verbatim post-fix evidence for
   it. No evidence, no RESOLVED.
9. **Append-only log.** Your edits to `issues_kb.md` are limited to: status
   markers on issue header lines, additive dated notes inside issue entries
   (fix deviation / handback), and one new appended fix-pass section at the
   end. Never rewrite, reorder, or delete existing content.
10. **No GPU work.** CPU-only probes only (`gmx <tool> -h`, `grompp`,
    `find`, `strings`, `ls`, `gmx dump`) — stricter than the audit's
    short-run exception, and enforced by construction: the transient
    container is never passed GPU devices. No `mdrun`, no benchmark runs.
    Reading a flag via `-h` is fine; running the tool is not.
11. **Never commit.** End with the step-7 diff + suggested commit message;
    committing is the user's action.
12. **Never switch the stack mode.** The agent's own LLM compute runs on the
    eGPU in the current stack mode; switching modes (`make gromacs` — or any
    `make <mode>` in the stack root, `scripts/switch-mode.sh`,
    `docker compose up --profile gromacs`) tears it down mid-session: a
    rugpull of your own compute. No GROMACS work ever requires a mode switch:
    all commands run in transient `docker run` containers, CPU-only (no GPU
    devices passed), in any mode, at any time. If the image is missing, stop
    and tell the user — building the image needs no mode switch.

## The run

### Step 0 — Preconditions

- Image present: `docker image inspect gromacs-hip-gfx1100:latest`. If
  missing: **stop and tell the user to build it** (hard rule 12) — never
  switch the stack mode to get a container; no running container is needed
  at all (probes are transient `docker run`, Paths table).
- `git -C $STACK_ROOT status --short .pi/skills/gromacs-sim/knowledge/`: uncommitted
  audit sections in `issues_kb.md` are fine (you append after them);
  uncommitted KB *content* changes are not — ask the user before proceeding.

### Step 1 — Scope (no container)

```bash
grep -E '^### I-' .pi/skills/gromacs-sim/knowledge/issues_kb.md | grep -vE 'RESOLVED|FIXED|FALSE POSITIVE'
```

Read each open entry in full (targeted — the file is large and growing).
Work list per issue: number, title, severity, `Files:`, evidence/probe type,
Recommended fix.

### Step 2 — Drift gate

```bash
docker run --rm gromacs-hip-gfx1100:latest gmx --version | head -3
```

Version string must match the "Gold standard" header. Mismatch → stop,
report, hand back to audit.

### Step 3 — Preflight (per issue, in number order)

Work dir: the session dir (the suite creates it fresh — every suite run
wipes it first).

**Baseline first**: run the probe suite — it wipes and regenerates
the session dir. Immediately copy `snapshot/03_block_verdicts.txt` and
`snapshot/03_matrix_verdicts.txt` to a `mktemp -d` path **outside** the
session dir and record that path in the todo list — the step-5 suite run
will wipe the originals.

For each open issue:

1. **Locate**: grep the KB for the text the entry quotes. If the stale text
   is already gone → the KB already reflects the fix: verify the *current*
   text against the build, then close as **ALREADY-FIXED** (no edit).
2. **Re-probe**: re-run the issue's minimal probe (the entry's evidence says
   which: `gmx <tool> -h`, grompp with `base.mdp` + the option, `find`,
   `strings`) — all in the transient container (Paths table). Issue still
   real → proceed. Disproved → **FALSE POSITIVE**: close with the disproving
   probe output (no edit).
3. **Verify the fix text**: every build-visible token in the fix's new text
   (option, value, enum, flag, tool, file) gets a build check —
   `02_help/<tool>.txt` / `gmx <tool> -h` for CLI; grompp + `base.mdp`
   (copy into the session dir, run in the transient container) for MDP, where
   `Invalid enum` names the valid values; `find`/`ls` for FFs, files, env
   vars. All confirmed → apply.
   A token fails → derive the correct text from the build, re-verify it,
   apply with a **Fix deviation** note. Cannot derive the correct text →
   hand back (rule 6).

### Step 4 — Apply

Minimal edits, one issue at a time, every file in the `Files:` list.
Re-read each changed region after editing. No collateral changes.

### Step 5 — Regression gate

```bash
bash .pi/skills/gromacs-kb-audit/scripts/probe_suite.sh
```

(wipes and regenerates the session dir = the post-fix state.)
Check:
- `snapshot/03_block_verdicts.txt`: every block `unknown=0 invalid=0
  obsolete=0` (errors/notes = known system noise, per the audit rubric).
- `snapshot/03_matrix_verdicts.txt`: only the documented false-positive-class
  (a) lines (topology/pull directives extracted from prose).
- Fixed CLI claims: map the changed lines to `snapshot/02_help/<tool>.txt`.
- **Stale-text sweep** (the suite has no coverage of prose): for each fix,
  grep the KB (excluding `issues_kb.md`) for the old text the issue entry
  quotes. A hit is either a **straggler** — the same stale claim in a file
  outside the issue's `Files:` list: fix it with the same verified text and
  note it in the fix-pass section (project convention) — or a documented
  false hit (e.g. README changelog spans describing removed options; judge by
  context, per the audit's false-positive class (b)).

Any signal NEW vs the baseline (diff the copied baseline verdict files
against the fresh ones) → revert that issue's edits, leave it open, note why.

### Step 6 — Log

Append one fix-pass section per `references/fix-pass-format.md`; add status
markers to the header lines of closed issues; additive dated notes for
deviations and handbacks.

### Step 7 — Report

- **Closed**: I-NN list, one line each (fixed / already-fixed /
  false-positive).
- **Left open**: I-NN list with handback reason (UNVERIFIABLE /
  UNRESOLVABLE / CONTESTED / regression-revert).
- **New-problem notes for the auditor** (discovered, not fixed).
- `git diff --stat .pi/skills/gromacs-sim/knowledge/` + suggested commit message:
  `KB: <date> fix pass (I-NN…I-MM) — <n> fixed, <n> closed, <n> left open`.

## Planning discipline

- **Todo list is the tracker**: one task per open issue + `scope + drift
  gate`, `regression gate`, `log + report`. One task in_progress at a time;
  mark completed immediately.
- **No sequential thinking** for a normal pass; `process_thought` only for
  genuinely ambiguous build output.
- **Resuming across sessions**: todo list (incl. the baseline temp path) +
  a WIP-marked fix-pass section in `issues_kb.md` are the state. Re-run the
  probe suite first to refresh the session dir (it wipes stale contents),
  then read the WIP section and continue.
